## 1. 时间与单位口径（R15 / PS-AC12 基础）

| 层 | 绝对时间口径 | 说明 |
|---|---|---|
| 展示（APP / WEB / Admin / 通知 / 导出） | **一律北京时间**（`Asia/Shanghai`） | 禁用设备默认时区格式化；报表、公告窗口、日志、CSV 同口径 |
| 存储 / 传输 | UTC Unix **秒**（`*.occurredAt`、`expiresAt` 等）或 UTC 小时桶 | 单位由字段名标明；毫秒级字段必须带 `Ms` 后缀 |
| 区间 | **半开 `[from, to)`** | 自然日 = 北京零点切分；"滚动 24h" ≠ "今天"，两者必须分别标注 |
| 播放进度 | 持续时长 `mm:ss` / `HH:mm:ss` | **不加 8 小时**；不得经时区转换函数 |
| Cron | 一律按 UTC 填写 | 现有 `content-sync.yml` `0 19 * * *`（北京 03:00）、`wrangler.toml` `0 4,16 * * *`（北京 12:00/00:00）均为正确 UTC 口径，**禁止把北京值原样填入 UTC cron** |

验收边界（PS-AC12 固定夹具）：同一时刻在设备时区为 UTC / 美洲 / 北京三种环境，所有绝对时间渲染必须输出同一北京时间；跨北京午夜的自然日分桶正确；`02:11:10` 的长片时长渲染不加 8h。

## 2. 安装实例与去重口径（R12 / §6.2）

- **`installId`**：安装时客户端随机生成（≥16 字节随机数的 hex/base64url），持久化于本机偏好存储；**不读 IMEI / ANDROID_ID / MAC**。卸载重装视为新实例，不冒称"人头"。
- **`instanceHash`**：服务端以受控密钥 HMAC 摘要 `installId` 后落库；密钥可轮换并保留版本映射（旧验证能力保留至 90 天留存结束），轮换不生成第二个去重主体。这只是去标识化，**不宣称不可关联的匿名**。
- **去重窗口**：90 天。发生隐私选择撤回 / 安装标识重置时切断关联并在响应中标注覆盖变化。
- **事件幂等**：`eventId` 唯一约束 + `(sessionId, seq)` 唯一约束，二者同时成立；重传必须复用 `eventId` 与 `(sessionId, seq)`，乱序迟到允许、同 seq 改 payload 拒绝。
- **口径纪律**：既有卡密 `sync`（按卡密关联）**不能**充当安装实例统计；同一设备重复提交幂等；预取请求不计热门点击；后台同步/预取不计活跃。
- **区域**：国家/地区展示把中国香港、中国澳门、中国台湾归入中国地区；`request.cf` 无数据一律标 `unknown`，不做推测。

## 3. 拟新增 API 契约（8 条路径 · 实施时落入 openapi.yaml）

共通要求（对全部新增路径生效）：
- 响应必带 `schema` 版本号；写请求必带唯一 `requestId` 与幂等语义；服务端时间一律 UTC。
- 错误码沿用现行闭集：校验错误 400、准入错误 401/403、无实体 404、冲突 409、限流 429、临时故障 503（`Retry-After`）。
- 用户退出/切换必须取消在途请求；失败不得伪装成功。

### 3.1 `GET /api/titles/{titleId}/bootstrap`（W3）

渐进详情的目标集快速入口；**只可从既有 title 事实增量实现**，能复用 `GET /api/titles/{titleId}` 达成时可不新增本路径（选择与理由记入 W3 台账）。

- 认证：可选 JWT（公开）；私密仍走双准入，未准入一律与未知同构 404。
- 查询参数：`ep`（目标集号，可选；缺省=首集/服务端可得的续播目标）。
- 响应：
  ```
  {
    schema: 1,
    revision: number,             // 公开目录/事实 revision，用于端侧失效
    item: ContentItem,            // 与现行目录卡片同源字段，不新增受保护字段
    targetEpisode?: { episodeNumber, title?, durationSeconds?, lineSummary?: { lineCount, hasNative } },
    catalogStatus: 'complete' | 'partial' | 'pending' | 'failed',
    generatedAt: number           // UTC 秒
  }
  ```
- 硬约束：**不得凭空生成集数**；`provider` 确实允许目标集独立解析才允许快返回；有原生描述符仍需合法原生解析步骤；目录未就绪时如实返回 status，不伪造。
- 兼容：不改变旧 `GET /api/titles/{titleId}` 完整响应；旧客户端零改动。

### 3.2 `POST /api/titles/{titleId}/prefetch`（W3）

邻近集元数据预热（JIT Lookahead [K, K+3]）；**只预热元数据，不搬运视频**。

- 认证：可选 JWT；body 无凭据内容。
- 请求：`{ requestId, episodeNumbers: number[1..4], reason: 'lookahead' | 'resume' }`。
- 幂等：同 `(workId, episodeNumber)` 在探测窗口内的重复请求幂等合并；限流去重（服务端窗口计数）。
- 响应：`202 { success, accepted: number, deduped: boolean }`；上游明确失败时 `200 { accepted: 0, reason }` 如实反馈，不 5xx 冒充。
- 与本地下载预取**分层**：本接口不触发视频分片预取。

### 3.3 `POST /api/telemetry/batch`（W6）

APP 遥测批量上报（事件 schema 见 §4）。

- 认证：可选 JWT；`installId` 在 body 内但服务端只信受控摘要。
- 请求：`{ schema: 1, events: AppEvent[1..20] }`，载荷 ≤ 32 KiB（超限 413 或 400，选型在 W6 落定并写测试）。
- 响应：`200 { success, accepted, deduped }`；服务端校验时间漂移、异常累计值、公开目录身份；IP 仅从可信边缘上下文读取，**不接受 body 伪造来源**。
- 离线队列：客户端有限队列（7 天过期、最多 N 批）；重传复用 `eventId`。

### 3.4 `GET /api/admin/app-analytics`（W8）

- 认证：AdminSession（同源、no-store、不反射 CORS；GET 无副作用）。
- 查询：`surface=app|web`、`from`/`to`（半开区间，UTC 秒；最长跨度 90 天）、`preset=24h|today|7d|30d`（与 from/to 互斥）、`channel`、`category`、`version`、`terminal`、`region`、`limit`、`cursor`。
- 响应：`{ schema, range: { from, to, timezone: 'Asia/Shanghai' }, metrics: {...}, coverage: { since, completeness }, generatedAt }`；未知值单列 `unknown`，不丢弃。
- 精度纪律：24h=滚动 24h（精确到分秒，来自小时基底 + 样本表交集判定）；"今日"=北京自然日；两者**分别标注**，不混称。

### 3.5 `GET /api/admin/rankings`（W8）

- 认证：AdminSession。
- 查询：`range`（同 3.4）、`scope=global|channel|category`、`channel`、`category`、`limit`（global ≤50、channel/category ≤20）。
- 响应：`{ schema, items: [{ workId, title, distinctViewers, playingSeconds, playStarts, sampleSize }], coverage, generatedAt }`；同时提供作品原始榜与证据合格 series/season 归一榜（防合集/分集分裂统计），归一榜带 `normBasis` 说明。
- 排序：区间独立有效观看实例数降序 → 有效播放秒 → 起播数 → `workId` 稳定序。不编造涨跌/完播率；小样本附 `sampleSize` 提示。

### 3.6 `GET /api/updates/manifest`（W9）

Web Bundle 热更新 manifest（签名契约见 §5）。

- 认证：免认证（签名自证）；响应 `Cache-Control: no-cache`（协商最新）。
- 响应字段（canonical 签名覆盖）：
  `schema`、`bundleVersion`、`webBuildId`、`minNativeVersionCode`、`requiredCapabilities[]`、`sha256`、`bytes`、`downloadUrl`（同源 `/dl/bundles/{sha256}.zip`）、`keyId`、`signature`、`issuedAt`、`rollout { percent, installHashBucket? }`、`releaseSequence`、`configRevision`、`bulletinRevision`。
- 控制语义：宿主只接受 `releaseSequence` 严格大于本机持久 `highestAcceptedSequence` 的 manifest；远程撤回须使用 `POST /api/admin/updates` 签发的 `controlSequence` 撤回消息（§5.3）。
- 兼容下限：`minNativeVersionCode` 以真实宿主能力为准，**不捏造 21110 为下限**；不兼容宿主必须收到明确拒绝而非白屏（PS-AC13）。

### 3.7 `GET /dl/bundles/{hash}.zip`（W9）

- 不可变包下载：`{hash}` 为 64 位 hex SHA-256，与 manifest `sha256` 逐字节一致；内容寻址，缓存 `immutable`。
- 同源自托管（与 `/dl/artifacts/*` 同级安全纪律）；404 = 对象不存在；不提供目录列举。
- 包为完整不可变 zip（首版不做差分；差分列为可选优化且必须完整包兜底）。

### 3.8 `POST /api/admin/updates`（W9）

- 认证：AdminSession + CSRF + 精确 Origin；只发布**已校验、已签名**对象，**不在线运行任意上传代码**。
- 动作：`publish`（激活新 bundleVersion）、`pause`（暂停灰度）、`recall`（签发 controlSequence 撤回消息，须严格大于原生持久 highestAcceptedControlSequence 且明确 targetHash）、`rollout`（installHash 稳定灰度）。
- 幂等：`requestId`；同请求同载荷重试幂等，冲突 409。
- 审计：与成功审计同批写入 `admin_audit_logs`。

## 4. APP 遥测事件 schema（W6/W7）

事件 kind 闭集：`app_foreground`、`foreground_heartbeat`、`play_start`、`play_progress`、`play_end`。

公共字段（每事件必带）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `schema` | int | 事件 schema 版本（首发 1） |
| `eventId` | string | 客户端生成唯一 ID（UUID/随机 128bit） |
| `installId` | string | 安装实例随机 ID（服务端摘要后落库，原值不存） |
| `sessionId` | string | 进程会话 ID |
| `seq` | int | 会话内单调递增；**换批次不重置** |
| `kind` | enum | 上列五值 |
| `occurredAt` | int | UTC 秒 |
| `appVersion` | string | 如 `2.6.7` |

播放类附加：`playSessionId`、`workId`、`episode`、`edition`、`lineKind`（`direct` / `native` / `proxy`）、`intervalStart`、`intervalEnd`、`deltaPlayingSeconds`。

**`deltaPlayingSeconds` 语义**：该 `seq` 唯一观影区间的**增量**（非累计播放位置）；累积值仅作交叉核验。倍速下按真实播放经过时间计（进度增量不直接当观看时长）。暂停/缓冲/后台/seek 无效时间**不计入**。

活动区间纪律：普通前台会话每次前台事件/心跳显式保存 `activityStart`/`activityEnd` 覆盖区间；`activityEnd` 上界为该事件 `occurredAt` 且长度最多 300s；下界不得早于实际 foreground 开始；`background` 事件关闭区间。心跳初拟 300s，UI 标注采样精度；未观测空白不得全天算在线。

其他纪律：
- title/channel/category 由**服务端核验目录**补齐，不相信端侧伪造剧名或小时桶。
- `play_start` 仅在收到 `playing` 且有效播放累计 ≥3s 时计数（唯一 `playSessionId`）；起播重试/切线/预取不重复计数。
- 跨北京小时/日边界按区间拆分入桶；跨小时覆盖在所有相交小时桶登记实例（防"事件结束点落下一小时"漏候选）。
- 载荷 ≤32 KiB / 每批 ≤20 事件；离线队列 7 天过期；每安装/session 限流；`eventId` 幂等。
- 采样/覆盖不精确时 UI 必须标注，不得写成精确在线时长。

### 4.1 实体与留存（W6 实施时转正式 additive migration）

| 实体 | 键与用途 | 初拟留存 |
|---|---|---|
| `app_event_dedup` | `eventId` 唯一 + `expiresAt`；重传去重，写入与指标更新须原子绑定 | 7 天 |
| `app_activity_buckets` | UTC 小时 bucket + `instanceHash`；有效前台/播放时间；跨日去重基底 | 90 天 |
| `app_event_samples` | `eventId`、`instanceHash`、`sessionId`、`seq`、`kind`、`occurredAt`、`activityStart/End`、`workId`/`edition` 及有效观影区间；不存原始 IP/卡密 | 90 天 |
| `app_play_instances` | `hourBucket` + `workId` + `instanceHash` + `episode`/`edition`；distinct 观看与时长 | 90 天 |
| `app_metric_rollups` | day/hour + boundedDimensions；请求/播放/地域累加，不以它独自计算区间 UV | 365 天 |
| `web_download_events` | `downloadId` + `occurredAt` + version/channel/terminal、受控来源摘要 | 90 天 |
| `web_page_event_samples` | `eventId` + `occurredAt` + `visitorHash` 可空 + surface/channel/terminal；精确 WEB 区间 PV/UV 基底 | 90 天 |

事务纪律：D1 无交互式事务，使用原子 batch / 条件更新；清理定时分批、DDL additive、旧表不 DROP；超 90 天只返回日汇总与完整性提示，不伪造精确去重。

## 5. 更新 manifest 与签名契约（W9/W10）

### 5.1 规范化与签名

- 签名字节：**RFC 8785 JCS** canonical JSON，UTF-8；排除 `signature` 字段；拒绝非有限数字与重复 key。
- `signature`：Ed25519 原始 64 字节的 **base64url**；`keyId` 只能命中宿主内置可信公钥集。
- 哈希与签名分工：SHA-256 只证明文件完整性，**不证明发布者**；发布者身份由独立 Ed25519 发布私钥签名（仅受控 CI/Secrets 持有，与授权 JWT 密钥**隔离**）。
- W9 必须输出至少一组 canonical 字节 / hash / 签名的**已知测试向量**供 W10 共用测试。
- 私钥轮换：新 key 通过受当前信任密钥签名的轮换消息或 APK 更新引入；保留旧包验证所需密钥。

### 5.2 单调序号（防重放/防降级）

- `releaseSequence`：manifest 单调递增；宿主持久 `highestAcceptedSequence` 于原生安全状态，**不随 Web 回退降低**。
- 版本显示值与安全序号分离，**不字符串比较语义版本**。

### 5.3 远程撤回

- 必须由 `controlSequence` **严格大于**原生持久 `highestAcceptedControlSequence`、且明确 `targetHash` 的签名撤回消息触发；
- 验签及应用成功后原子推进最高值；重复或更小的控制序号拒绝；
- 同一 `controlSequence` 同 payload 可作已执行幂等 ACK，但**不得再次激活**；
- 本地回上一健康包不视作远程接受旧 manifest。

### 5.4 下载与切换状态机

`check → download → verify → stage → pending → activate → healthy`；失败进入 `quarantined / rollback`。

- 断点续传必须校验对象版本；zip-slip / 解压炸弹 / 重复覆盖限额防护。
- 包临时区**不与视频 512MB 配额混算**，但显示占用。
- 只在冷启动或用户明确确认的空闲态切换，**不中断播放**；健康握手初拟 15s 可调，排除已知系统挂起；上一健康包 + 内置包双回退。

## 7. 基线：冷暖起播请求瀑布（2026-10-10 · HEAD 3610e64 代码路径分析）

以"点击卡片 → 详情可交互 → 起播"为主线。现状（W1 施工前）：

**冷打开（无任何本地缓存）**
1. 点击 → `player-host.open()` 同步建层，**全屏 loading 覆盖**（无标题、无骨架）；
2. `runtime.refresh()` — 本地读偏好/授权，无网络；
3. `GET /api/titles/{id}`（**主等待点**；真实上游冷详情用户观察 >10s，样本《糯糯下山，师兄们都慌了》）；
4. `promote()` 写标题 → 创建播放器 → 详情正文装配；
5. 播放器内 `manifests.load(workId)` — 内存/磁盘未命中则 **第二次 `GET /api/titles/{id}`**（同一路径、两种适配）；
6. 线路解析：清单 `lines[0].mediaUrl` 直连，或回退 `GET /api/episodes/{id}/playback`；
7. 引擎组建（ArtPlayer+hls 或 ExoPlayer）→ 首帧。

**暖打开（同进程、同剧目，缓存未过期）**
- 第 3 步 **仍发全量网络请求**：`api.title()` 当前无任何缓存 → **不满足 PS-AC01「暖切版本不重复全量 title 请求」**（W1 修复目标之一）；
- 第 5 步命中内存/磁盘清单；磁盘 TTL 判定误用 `generatedAt` 而非 `cachedAt`（W1 修复目标之二）。

**记录方法（W1 现场执行）**：真机 + 慢网络对照组（《糯糯下山》冷详情 / 《让你代课…第三季》双版本），录 30 次冷/暖打开的 p50/p95、请求瀑布、媒体事件与缓存状态；本节的代码路径分析是测量对象清单，**真机数据未采集前不得当作已达标**。

## 8. 实施纪律（把本文件落入现行契约的时序）
