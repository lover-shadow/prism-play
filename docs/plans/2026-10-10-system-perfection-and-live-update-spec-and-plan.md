### 2.2 技术边界与不得偷换的需求

- 快速显示 UI 不等于视频首帧已解码；不能承诺所有网络 16ms/0.8s 起播或 0ms 跨集。
- 预下载文件不等于播放器会读取它。必须实现双引擎缓存读取接驳、取消与回收，不能只写设置开关。
- “全集”可能只是完结状态，“精编”可能删剧情；禁止关键词加 1000 分便替换用户当前季/版本。
- 缓存长效是工程策略，不保证 CDN 常驻、全球命中或永不被封；14 天是可回收缓存保留窗口，不是所有数据的新鲜期。
- Wi-Fi 可能是手机热点/计费网络；未知网络与被系统标为 metered 的网络默认不主动预取，用户显式“所有网络”才覆盖。
- 主动预缓存只在 APP 前台观影/浏览时执行；本计划不新增 Android 常驻后台下载服务。
- 海报轮换只改变真实候选选择，不能造“高分、热门、可播”依据；榜单默认用于受保护 Admin，不擅自将 APP 变为投流分发平台。
- 数据统计不称“真人数”或“绝对匿名”；安装实例标识、IP 和观看记录均应最小化采集、披露与保护。
- 不在本轮新增私密专属埋点硬断言；复用现行数据准入/存储契约，既有“不持久化/不上报”规则的改变要单独同步 SPEC。不能把聊天里的简化表达当成删除所有既有约束的授权。
- 不新增 DRM 绕过、不上传视频、不做云端实时 75 集拼接/转码。虚拟缝合并非因 200KB 包体而必不可行，但非本次选定路径。
- 广告清洗二期、Workers AI/Vectorize、公开榜单商业化、原始 IP 永久保存不在本次范围。

## 4. 播放与缓存 SPEC

### 4.1 一次作品事实读取与渐进显示

1. 公共卡片预填仅包含现有合法展示字段，不伪造分集/线路；首个 await 前挂载 shell/title/placeholder，状态只覆盖媒体区域，不遮整页详情。
2. 统一详情与线路缓存读取同一原始标题响应，再分别适配 UI 与播放器，命中同一 workId 的并发请求合并；失败不缓存为成功。
3. 缓存记录分开 `generatedAt`（上游事实生成）、`cachedAt`（本地获取）、`revision`、`expiresAt`；TTL 不能用 generatedAt 代替 cachedAt。
4. 初拟进程 LRU 20 部，复用既有磁盘标题缓存；默认公开标题 6h 本地窗口保持兼容，配置/撤片/源变动以 revision 失效，勿另造互不一致的一小时缓存。
5. HTTP 浏览器缓存、标题磁盘缓存、HLS 清单、视频分片分别处理；清公开缓存要使活动内存与磁盘一致，HTTP 长缓存需服务端新鲜校验/版本键配套，不能承诺“清盘即全刷新”或“最长6h必然收敛”。
6. cache hit 先构建 UI、再并行完成必要网络准入/更新；cache miss 首集/续播集优先，完整选集与季关联后台补齐。新卡片只有 title/cover 时不能凭空解析第一集，须 W3 bootstrap 支持。
7. 作品切换用 generation + AbortController 防迟到结果写错；只保留所需公开实体，旧引擎资源有序释放，跨引擎不串源、不覆写断点。
8. 断点绑定 workId+episodeId+edition，不因候选默认排序改变已选择版本；不同版本时间线未有章节点映射时，不盲用同一播放秒数。

### 4.2 季/部发现与合集优选

- 缓存先列出已知合法关联，discover 并行检索系列；`pending/partial/failed/complete` 四态必须区分；空结果只有 complete 才可短缓存，失败/pending不得冻结“没有其它季”。
- 系列关系最少包含 `seriesKey`、`seasonNumber`、`editionKind`、`workId`、`identityEvidence`、`updatedAt`。名称解析只是候选线索，跨来源需已有可信映射或经审核的关系，不仅同名合并。
- 优先只在“同作品、同一季、内容完整、可播、授权有效”的版本间选择；已提供用户偏好/续播版本优先，首次进入才默认完整合集。
- 合集与分集可用集数、时长、来源说明、章节点及人工核验组合判断；不完整精编单独标注，不自动替代完整版。
- 长片 UI 显示“合集 · 02:11:10”，分集版显示“75 集”；不能把“1 个媒体条目”文案写成“共1季”。缺少时长字段显示未知，不编造。
- 选择季/部保留 shell，已解析关系与版本立即复用；异步新增候选不得突然切换正在播放版本。

### 4.3 手势仲裁与控制条

- 中心区域初拟为画面水平 30%～70%、垂直 20%～80%的可操作媒体区；用实测调整后统一常量，排除菜单、按钮、字幕设置、状态错误卡和系统安全区。
- 中央单点翻转真实 play/pause；外围单点唤出/收起控制条；双击仅在左右外围保留现有 ±10s。中央双击不得产生两次乱跳或兼作 seek。
- 按下即进入候选态；轴向移动超过约 12px 后进入横向 seek 或中央纵向切集，不再触发单点；长按倍速优先仲裁，松手恢复；多指/锁定/菜单状态抑制媒体手势。
- 横滑先预览目标时间/偏移，不每次 pointermove 重启解码；抬手只提交一次 seek，限制在有效时长；未知 duration 时不猜位置。短片 `mm:ss`，长片 `HH:mm:ss`。
- 中央上滑下一集、下滑上一集；方向判定后锁轴，抬手纵向位移至少max(48px,媒体区高度12%)且纵向大于横向1.5倍才提交一次切集，12px只是进入候选态不是立即换集；未达阈值取消。左右边缘纵滑保留亮度/音量；首末集给明确反馈，单媒体合集不虚构下一集；滑页面详情不切集。
- 单点判定沿用300ms双击窗口；中央两次近距轻点合并为一次play/pause，不做seek或双翻转；外围双击确认后取消待发单点。所有参数集中定义并由W2固定夹具与真机验证。
- 正常 playing 且无操作/菜单时，3.5s 后隐藏；pause/waiting/seeking/error 或主动菜单保持可控；全屏切换重新评估。先复现既有“全屏才计时”与 CSS 关系再改，不强行让非全屏出现新工具条。
- 视觉反馈使用 Lucide/Design Tokens，图标短暂显示；暂停时保留可发现的恢复入口；对 ArtPlayer 与原生 controls 均执行，避免两套控制状态撕裂。

### 4.4 视频缓存读写契约

| 项 | 规定 |
|---|---|
| 策略 | `wifi_only` 默认、`all_networks` 显式授权、`disabled`；变化立即取消不符合策略的主动任务，当前播放仍可正常下载 |
| 空间 | 档位 256/512/1024/2048/3072 MiB，UI 标 MB/GB并说明换算；默认512；不预分配；文件/索引/临时下载共受上限管理 |
| 缓存键 | workId、edition、episode、line/provider、资源路径/版本、byte range、加密/初始化信息；不可随意删 URL 签名参数造成内容碰撞 |
| 文件写入 | 原生流式写二进制与原子 rename，避免 JS base64 全集复制；大小/范围一致才提交；进程死亡清理残留临时片 |
| 读取 | hls.js 通过真实 loader 接驳；Media3 通过 CacheDataSource 或现有自定义 DataSource 兼容层，明确加密字节与密钥有效期，不持久化解密秘密 |
| 淘汰 | LRU按真实访问；正在读写资源 pin；空间不足取消低优先级任务，不删正在播的分片；降低上限后受控清退，无可淘汰空间暂停新增 |
| 失效 | 媒体404/签名过期/作品撤片/线路版本变更只失效对应条目；缓存存在不等于离线授权，无合法可用媒体不能承诺离线播放 |
| 设置 | 当前使用量/上限、策略说明、清空按钮；清空取消预取、回收非活动资源，保留历史、收藏与凭据；统计异步但如实标记清理中 |
| 资源 | 保留至少 max(512MiB,磁盘容量5%)可用空间作为初拟阈值；低电量/温度/内存压力暂停投机预取，当前播放优先 |

缓存格式与插层矩阵（W4硬门禁）：公开HLS缓存原始合法分片/byte range，加密HLS保存密文不落密钥；公开原生CENC的HTTP Range密文缓存必须置于`ProbeCencDataSource`解密调用之前，不能把解密后的DataSource再包进磁盘CacheDataSource。CENC索引/密钥与解密缓冲保持内存；私密按现行契约不落磁盘。测试必须验证磁盘字节等于上游密文且解码读取正常；任何路线不能满足时仅该路线降级RAM，设置与诊断明确显示支持范围，不能谎称两引擎持久缓存均已支持。

### 4.5 分级预取与连续播放

#### 4.7.4 P2-04/P2-06：目标集两阶段装配与元数据探针

## 5. 云端获取与更新缓存 SPEC

### 5.1 三层元数据缓存与轮进轮出

- L1：进程/边缘 response cache 作为加速器；L2：已有 R2 内容寻址事实包与 D1 目录索引作为可恢复事实；L3：上游有界抓取。
- 不假定 `cf.cacheTtl` 命中自动刷新写入时钟，不假定 Cache API 全球复制，CDN可提前淘汰；14天只作为 L2 已确认完整作品的候选闲置保留窗。
- 新鲜期与保留期分离：连载目录默认30min、新发现/未确认1h、已确认完结24h；后台确认无变更后可逐步放宽新鲜期至7天；闲置保留上限14天。旧版本数上限2；单元数据对象上限1MiB；初拟活跃事实池1000作品的限制仅作用发现缓存，不删除正式目录。
- 每6h最多合并一次 lastAccessTouch，不每次点击写KV续期；同 work 单飞刷新。LRU/闲置清理不得删除正式发布事实或仍被版本引用的R2对象。
- 返回 stale 只限当前准入仍有效、媒体地址仍可用且在允许陈旧窗口内；后台完成更新才推进 validatedAt；过期签名、撤片、来源停用必须立即更新或拒播，不用 stale撑过去。
- 失败有限退避、显示可行动重试；HEAD支持不足改条件GET，用ETag/Last-Modified时保存验证证据。
- `ctx.waitUntil` 不是永久作业进程；有界工作与游标保留，超预算交后续巡检，不在用户请求里循环全库。

### 5.2 四项获取优化的完整定义

1. 租约：初始30s、每约10s或批次前续租；ownerToken条件更新；失锁立即停止后续写；正常/临时失败 owner匹配释放；冷却状态与lease分开。已有 finally释放不是未实现，解决目标是进程被杀时300s锁残留及续租竞态。
2. 双轨：前台预算起点2请求/3s、后台24请求/25s、并发最大3；实际按provider协议必要步骤调整，预算不是成功时延承诺，24请求不等于24集。整段DNS/重定向/读体/持久化均在wall预算内，CPU单独记录。
3. 长效缓存：按§5.1，不对所有上游抓取无差别cacheEverything；包含身份/密钥的POST不入共享缓存，不宣称手动Connection头可以控制Workers socket池。
4. 邻近集预热：正在看K集时优先[K,K+3]的未就绪元数据，续播优先；APP有效播放约70%或按剩余时长发一次幂等探针（取更早触发），限流去重；与本地下载预取分层，不把视频搬到Worker。

### 5.3 首播旁路与 HLS 单变体优化

- 已有详情事实可直接返回；冷详情拆成“轻量可核验目录/目标集”和后台完整事实持久化。只有provider确实允许目标集独立解析，才能快返回；有原生目录描述符还需合法原生解析步骤。
- 新 bootstrap 响应含 item、targetEpisode、可用line/native、目录状态与revision；不能生成没有依据的集数或本地ID与服务端ID混用。
- 保留旧title完整响应兼容旧APP；新增客户端统一事实适配，避免重复GET同一完整payload。
- 主清单仅有一个合法视频变体且无额外音轨/字幕/I-frame约束时可云端折叠；使用重定向最终URL作为相对URI基址，保留HLS KEY/MAP/BYTERANGE语义；多码率保持ABR结构。
- 折叠仍需上游两次fetch，只减少客户端往返；失败安全回退现有清洗链路；不能把该优化变成新增广告识别规则。

### 5.4 免费资源与容量验证

- 2026-10-10官方Workers限制核查：Free HTTP CPU10ms、内存128MB、外部子请求50/request、同时出站连接6；响应体150～200KB本身不是禁止条件。
- CPU不含网络等待，但包含解析、哈希、序列化；有效预算需把重定向与存储操作按官方计数分类计算，不能用包体或请求数单独断言可行。
- 初拟100活跃实例、每日60min/实例、心跳300s约1200条心跳/日；每条涉及去重/活跃桶/时段/作品聚合多次写，需实测行读写、索引与全账户配额，再决定批量/降采样。
- 不宣称“永不爆库/月增量<1MB”；保留配额预警、降级与总开关。R2只放元数据和包，视频流量不上云；未知CPU/预算不得以升级收费套餐替代优化，收费另行授权。

## 6. 统计、时区与热更新 SPEC

### 6.1 指标字典（WEB与APP分开）

| 指标 | 严格口径 |
|---|---|
| WEB PV / UV | 成功页面访问请求 / 同意统计且可识别浏览器的区间去重数；机器人和拒绝统计覆盖须标注 |
| APK下载量/时间 | 下载触发事件和请求到达时间；Range/重试合并，同一downloadId或短窗口会话计一次，不冒称完成下载/安装 |
| APP活跃 | 前台使用或有效播放的安装实例区间去重数；只打开不播放也算；后台同步/预取不算活跃 |
| DAU / 24h | 北京自然日去重 / 精确滚动24h去重；分别标注，不能相互混称 |
| WAU / MAU | 滚动7天/30天安装实例去重，不是各天DAU相加；卸载重装可能成为新实例，不冒称人头 |
| 有效起播 | 收到playing且有效播放累计≥3s的唯一playSession，重试/切线/预取不能重复计数 |
| 播放时长 | playing且媒体确实前进的实际观影wall seconds，暂停/缓冲/后台无效时间排除；倍速进度增量不直接当观看时长 |
| 请求作品 | title/bootstrap/播放入口请求workId与时间；命中本地缓存不会产生云请求，因此不是全部观看记录 |
| 热榜 | 默认区间独立有效观看实例数降序，次按有效播放秒、起播数、workId稳定序；完成倾向另列，不将长片与短片时长直接混为唯一热度 |
| 地域 | 服务器可验证连接IP所映射的地区，不是精确居住地；VPN/代理/移动网出口/未知值明确标记 |

### 6.2 事件契约与统计存储

- 安装随机ID用于去重，不读IMEI；服务端受控密钥摘要并轮换，版本可迁移；只是去标识化，不宣称不可关联的匿名。既有卡密sync不能代替安装ID。
- 事件kind：`app_foreground`、`foreground_heartbeat`、`play_start`、`play_progress`、`play_end`；服务端另记录title请求和download触发。前台启动/退出与播放退出结算；心跳初拟300s、进度增量批量合并。
- 每事件含schema、eventId、installId、sessionId、seq、kind、occurredAt、appVersion；播放类增加playSessionId、workId、episode、edition、lineKind、intervalStart/intervalEnd、deltaPlayingSeconds。deltaPlayingSeconds为该seq唯一观影区间的增量，不是累计播放位置；累计值仅作交叉核验。title/channel/category由服务端核验目录补齐，不相信端侧伪造剧名或hour。
- 重传必须复用eventId和(sessionId,seq)，服务端唯一约束两者并原子插入去重+更新指标；乱序允许迟到但同seq不得改payload，冲突拒绝。按区间拆分北京小时/日边界，跨后台切换关闭区间；seq不能因换批次重置。心跳活跃为观测点，播放活跃为核验观影区间；普通前台会话每次前台事件/心跳明确保存activityStart/activityEnd覆盖区间，上界为该事件occurredAt且长度最多300s，下界不得早于实际foreground开始，background事件关闭区间。采样覆盖不是精确实际在线时长，UI标采样精度；不能把未观测空白全天算在线。
- 统计标识在90天去重窗口保持稳定；服务端日常密钥轮换保留版本映射/旧验证能力至留存结束，轮换不生成第二个去重主体。发生隐私选择撤回/安装标识重置需切断关联并标覆盖变化，不强行还原用户。
- batch最多20事件，载荷最多32KiB；服务端校验时间漂移、异常累计值、公开目录身份与上报适用范围；离线重传有限队列且7天过期；每安装/session限流与eventId幂等。
- IP仅从可信边缘请求上下文读取，不接收客户端body伪造来源；Geo优先`request.cf`可用字段，无数据标unknown。国家/地区展示把中国香港、中国澳门、中国台湾归入中国地区，不当作独立国家。
- “静默”指不弹窗干扰，不是秘密采集；复用隐私说明/选择与退出能力，默认汇总，诊断完整IP访问受保护管理员权限与审计，默认不保存完整IP；业务要求原IP明细时先确认用途、留存与契约。

### 6.5 热更新与通知/片源控制面

- 本次必须交付生产可用热更新；新宿主需一次APK安装，不对已安装旧APP承诺免安装获得新原生插件。
- 三独立渠道：Web Bundle代码、公告/更新通知、目录/片源配置。各有schema/revision/生效时间/兼容范围/回滚指针，不能每换片源就发代码包。
- 源站地址/商业策略保持服务端配置，公开UI不暴露上游源名；APP只消费已支持provider adapter与来源schema，新增原生能力仍需APK升级。
- 更新manifest拟字段：schema、bundleVersion、webBuildId、minNativeVersionCode、requiredCapabilities、sha256、bytes、downloadUrl、keyId、signature、issuedAt、rollout、configRevision、bulletinRevision；不捏造21110作为当前兼容下限，不使用伪Unix时间。
- SHA-256证明文件完整性，不证明发布者。独立Ed25519发布签名私钥仅受控CI/Secrets保存，公钥在原生宿主；签名覆盖canonical manifest、包hash、大小、版本与能力；与授权JWT密钥隔离。
- 签名字节采用RFC8785 JCS规范UTF-8，排除signature字段、拒绝非有限数字与重复key，signature为Ed25519原始64字节的base64url；W9输出至少一组canonical字节/hash/签名已知测试向量供W10共测。所有影响安全/选择的字段包含在签名payload中，灰度客户端对已签rollout按installHash稳定判定。
- manifest添加单调releaseSequence；宿主持久highestAcceptedSequence于原生安全状态，不随Web回退降低。允许远程撤回时必须另有controlSequence严格大于原生持久highestAcceptedControlSequence且明确targetHash的签名撤回消息；验签及应用成功后原子推进该最高值，重复或更小控制序号拒绝。同一controlSequence同payload可作已执行幂等ACK但不得再次激活。本地回上一健康包不视作远程接受旧manifest。版本显示值与安全序号分离，不字符串比较语义版本。
- keyId只能命中内置可信公钥集；新key通过受当前信任密钥签名的轮换消息或APK更新引入，保留旧包验证所需密钥。W9/W10用旧合法manifest重放、未知key与合法撤回夹具证明拒绝/接受边界。
- 下载状态：check → download → verify → stage → pending → activate → healthy，失败进入quarantined/rollback；断点续传校验对象版本，zip-slip/解压炸弹/重复覆盖限额；包临时区不与视频512MB配额混算，但显示占用。
- 首版采用完整不可变包；差分列本次可选优化，必须基准版本匹配/完整hash再验证，否则下载完整包，不以差分阻塞核心交付。
- 使用Capacitor 7官方支持的本地资源加载路径或审查合格现成插件，W10先做真机spike，再锁定方案；禁止未验证就依赖私有API重定向。依赖引入核查许可、维护、联网与数据边界。
- 只在冷启动或用户明确确认的空闲态切换，不中断播放；启动健康握手初拟15s可调且排除已知系统挂起；不把任意5s慢启动自动判为白屏。上一健康包+内置包双回退；远程降版必须显式签名撤回指令，不能随意接受旧manifest。
- Admin只发布已校验、已签名对象，不在线运行任意上传代码；小范围稳定installHash灰度，支持暂停/撤回/审计；控制面失效继续用健康包。
- 公告沿用现有已读revision及播放避让；新增能力支持生效期、最低/最高宿主、强/弱提示等级，发布成功才通知，断网不重复骚扰。
- 片源/目录更新复用既有manifest增量同步，配置revision变更使对应标题/线路缓存失效，不全盘删观看历史；端侧多轮抓取失败保留可用旧代并给出状态。
