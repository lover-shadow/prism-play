## 一、 产品定位与问题陈述

### 1.1 背景与痛点陈述
**待验证的问题假设**：部分移动端观影用户希望降低播放前操作与广告干扰，并在通勤、睡前场景获得连续播放体验。以下竞品评价、用户比例与性能主张沿袭历史方案，尚无本项目可复核的样本或测试条件；不得作为商业上线保证或法务结论。MVP 以已获合法分发权限的内容样本验证“选片→选集→播放→续播→分享→核销”闭环。

### 1.2 核心设计哲学
《光影Play》（Prism Play）是 PrismOS 家族面向私域高品质影音圈子打造的工业级全景流媒体终端。坚决执行以下四项基本哲学：
1. **大视界动态流媒体拓扑**：公开频道固定四个初始入口【短剧精选】、【院线电影】、【热血动漫】、【人文纪录】；【个人探索】仅有效 B/Y/S 授权且本次启动用户手动开启后才可见，冷启动默认关闭；动态增减仅限经授权内容与独立准入约束。
2. **真沉浸流媒体质感**：告别旧版 WebView 裸奔与外部子进程套壳，基于工业级跨端容器（Capacitor 7）与专业开源播放器（ArtPlayer.js），打通 Edge-to-Edge 边到边全面屏、左右双滑手势调控、后台常驻播放与定时关闭；
3. **极简点开即播分享**：分享链接剥离一切冗余落地宣传页，实现 Web 网页端（`play.prismos.org/s/:id`）“点开直接起播对应剧集，播放完毕瞬间精准截流引导下载”；
4. **云端自动化卡密闭环**：废除落后的人工报送设备码算号机制，推行预制卡密 + 客户端输入自动核销绑定 DeviceID + Cloudflare D1/KV 边缘下发 JWT 凭证的零人工运维模式。

### 1.3 目标用户画像
- **主力用户画像（历史假设，比例待用户研究验证）**：
  - **群体特征**：22-45 岁网剧爱好者、下沉市场与一二线通勤族，碎片化时间追剧，常在地铁、公交、睡前躺卧观影；
  - **技术水平**：非极客群体，拒绝任何复杂的接口配置代码，追求“打开即看，画质清晰，没有弹窗干扰”；
  - **核心诉求**：单手大拇指快速滑屏选剧、双击快进、睡前定时自动关闭、戴耳机听剧后台不中断。
- **次要用户画像（历史假设，比例待用户研究验证）**：
  - **群体特征**：私域社群付费会员、影音发烧友，拥有平板与支持投屏的大屏电视；
  - **技术水平**：中等，注重隐私性与观影体验，具备卡密兑换概念；
  - **核心诉求**：私密分类保护、投屏到大屏继续连播（大屏投屏 DLNA 为 Backlog，非本期 MVP）。

### 2.2 我们的核心差异化破局点
1. **纯净零广告工业级流媒体**：全链路去除任何开屏、插播、横幅及悬浮广告，还原本质观影体验；
2. **经授权的多源切换**：同一授权剧目可关联多个允许使用的播放源；可用源按可达性选择，失败时恢复到同一剧集接近原播放进度，不承诺未经测量的首帧或无感切换时延；
3. **端原生级深度体验打通**：支持 Android 原生前台服务（锁屏常驻控制）、TelephonyManager 来电自动恢复、原生亮度及音量硬件映射；
4. **低摩擦单集体验**：H5 播放页不设下载前置门槛，先看一集、播完再提示“继续看请下载 App”；实际转化率以埋点数据评估，不作预设承诺。

## 三、 客户端功能架构与动态频道模型

### 3.1 顶层导航拓扑（云端动态“大视界”架构）

#### 3.1.1 第一层：综合首页与真实公开频道
启动默认进入本地综合首页，随后固定展示【精彩短剧】、【电影仓库】、【人文纪录】、【动漫】；这五项不对应五个云端频道。后四项分别使用既有真实 channelId `drama`、`movie`、`documentary`、`anime`，以云端 `ChannelItem.name` 作为相应频道展示名，保留各自真实分类。综合首页跨四个公开频道读取候选池，不新增 `home` 云频道、伪造来源ID或API。个人探索不在固定公开导航、综合首页或公开推荐中；仅有效 B/Y/S 授权且本次启动手动开启后依原双准入规则另行出现。频道和剧目必须限于已取得相应分发权限的内容；不显示上游品牌，不等于可绕过授权义务。
1. **【精彩短剧】（本地综合首页之后的公开频道）**：
   - 收录已获合法分发授权的短剧与漫剧样本；
   - 对配置来源的同剧多源做强映射证据归一，同名不足以自动合并；云端从授权有效的分集源优选可用流；
   - 剧目卡仅展示有可信数据的清晰度、完结状态与集数；缺数据时不展示相应角标。
2. **【电影仓库】（channelId `movie`）**：
   - 仅上架具有该端分发授权的电影和系列作品；
   - 有可信元数据时展示片长与清晰度；第三方评分须取得显示许可并注明出处，否则不展示。
3. **【人文纪录】（channelId `documentary`）**：
   - 提供已获授权纪录片样本；未经许可不得使用第三方片库与商标作可播放承诺。
4. **【动漫】（channelId `anime`）**：
   - 按授权范围提供动画样本，缺少有效分集数据时不展示可播放入口。
5. **【个人探索】（独立双准入入口，不是固定公开导航第六项）**：
   - 专属高阶个人探索内容库，**对外绝不宣传、绝不作为公开卖点**；
   - 官方公开文案、卡密权益说明与商业引导中，**严禁出现任何“解锁私密/成人内容”等违规噱头**，仅表述为“纯净免打扰 / 高速专线”；
   - **交互授权与免责声明**：
     * 仅当本设备持有**未过期且未撤销的 B/Y/S 高级授权**时设置中心才露出【个人探索模式】开关；无卡、Q/A 普通卡及过期卡不露出；
     * 本次启动首次勾选时提示内容适龄与授权来源信息，用户主动确认后才可进入；免责声明不取代年龄分级、内容审核、取得授权及当地适用法律义务；
   - **【每次启动默认关闭】铁律（防社死 / 防儿童误触 / 法律绝对防线）**：
     * **系统严禁将“个人探索开启状态”持久化存入磁盘**；
     * 每次完全退出 App 并重新进入、或冷启动时，**个人探索模式 100% 默认自动重置为【关闭状态】**！主视界永远呈现阳光合规的短剧/电影/动漫/纪录片；
     * 用户若需观看，必须在每次进入软件后，前往设置手动再次打开；
   - **绝对物理隐形与零分享铁律（合规生死线）**：
     * 前端与接口双层隐藏：除有效 B/Y/S 且本次会话手动确认开启外，频道、源、目录、分集与代理均不得向请求者提供个人探索数据，客户端 DOM 不渲染；关闭或冷启动后会话许可失效；服务端不得仅依据长期 JWT 认定已手动开启；
     * **个人探索频道下的所有剧集与视频，前端 100% 物理剔除【分享此集】/【分享】按钮**；
     * **Cloudflare 边缘分享网关（`/s/:id`）严格阻断个人探索内容**：一旦请求的剧目属于个人探索分类，边缘路由立即返回 404 Not Found，绝对禁止任何敏感私密内容外流至微信或公网；
   - **硬件级防截屏/防录屏（FLAG_SECURE 银行级防泄密）**：
     * 当且仅当用户处于【个人探索】频道浏览或播放时，Capacitor 原生层动态向当前窗口附加 `WindowManager.LayoutParams.FLAG_SECURE`；
     * **防截屏生效**：此时系统快捷键截屏强制弹出“受安全策略限制无法截屏”或截出一张全黑图片；
     * **防录屏与防偷窥**：第三方录屏软件录制出来全片黑屏；切出应用到多任务卡片预览（Recent Apps）时自动展示为全黑安全遮罩，彻底杜绝周围人偷窥或后台进程恶意抓屏；退出该频道后自动恢复；
   - **本地零存储 · 阅后即焚（RAM-Only In-Memory 绝密隔离）**：
     * **零历史留痕**：个人探索频道下观看的任何剧集，系统严格拦截并物理禁止写入本地历史记录数据库；
     * **零断点续播**：不保存进度秒数，首屏置顶续播位绝不出现任何探索频道剧集卡片；
     * **零持久化**：个人探索内容的标题、封面、播放历史、进度、媒体响应与分片不得写入客户端持久化存储或可恢复的离线缓存；关闭频道立即清理应用可控内存引用。操作系统、第三方组件和网络中间层的缓存须由实现与安全测试确认可抑制，未经验证不得宣称硬件级物理抹除。

#### 3.1.2 第二层：吸顶联动横滑次级流
当选中综合首页或任一真实公开频道时，联动激活下方吸顶横滑栏：
- **前置快捷榜单胶囊**：`[今日爆火]`、`[偏好推荐]`、`[最新上线]`；
- **题材标签胶囊**：`[都市]`、`[战神]`、`[逆袭]`、`[甜宠]`、`[古装]`、`[悬疑]`、`[重生]`、`[神豪]`、`[玄幻]` 等；
- 用户横滑切换标签时，内容流支持局部平滑更新，无整屏白屏闪烁。

#### 3.1.3 首屏置顶续播位
- 综合首页顶部可展示最近一次公开观看的剧名、集数与断点；私密和未知内容不进入推荐或续播。
- 点击继续观看进入对应剧目，并按播放契约恢复有效断点。

### 3.1.4 综合首页推荐与公开目录
首页每个完整展示轮次以60部作品为目标，目标配额为AI短剧20、证据合格真人短剧4、电影12、纪录片与动漫6、跨公开频道偏好18。候选先作公开过滤和全局去重；缺少真人质量证据时不贴口碑标签、不强凑低质量作品，并按 HP-05 记录配额偏差或返回不足60条。AI只依据可信类型字段。四公开频道目录仍每页/分片60部作品，作品不等于单集；综合首页不发起虚构频道请求。

同代公开列表字段为可选：清洗真实摘要最多240 Unicode code points；副标签来自可信受控题材/风格，最多6项、每项最多12 code points；发行年份只取明确四位年份字段，不从上架或采集时间推导；地区与语言各最多64 code points。字段缺失时省略并压缩信息块。

### 3.1.5 合法内容目录与分集闭环（MVP 前置）
- 上线前由内容负责人提供至少覆盖四个公开频道的**可核验授权样本**、授权平台/区域/期限、剧目与分集映射；缺授权或到期的内容不进入可播放目录。个人探索样本亦不得豁免授权与内容审核。
- 目录查询须支持频道及二级分类筛选、分页；每张卡有稳定内容 ID、标题、封面、内容类型、总集数或片长、可用状态。点开卡片能获取该内容详情、按顺序排列的分集 ID 与可播放状态，再以内容 ID + 分集 ID 请求受保护播放地址/代理，不把上游密钥暴露在客户端。受保护代理的 HLS 清单/分片/封面及 Range 请求须逐次验证当时 D1 发布状态，私密还须绑定有效授权与本次会话，不得仅凭可复制的代理 URL 放行；原生 HLS 子请求是否可逐次携带会话须真机证明，未证明前私密取流关闭。
- 同名归一不得仅以标题合并，需用经审核的内容主键映射；同名异剧必须分别展示，失效源不影响已上架内容的身份。空分类展示无内容说明，不伪造榜单数据。
- 片单授权到期、撤片通知或上游不可用时立即禁止新播放及分享访问，并明确提示内容暂不可用；分享 `/s/:id?ep=` 必须对公开内容与有效分集再次鉴权，个人探索一律 404。正式接口路径和字段以联审后的 `docs/03-contracts/openapi.yaml` 为准，不得以源列表代替剧目目录。

### 3.2 海报排版四模切换系统
界面顶栏提供排版模式切换按钮，支持用户根据握持习惯与审美自由切换，客户端本地持久化用户偏好：
1. **中图紧凑网格（3列 · 默认）**：
   - 海报比例固定 3:4，一屏紧凑呈现 9~12 部，适配单手大拇指极速扫剧；
2. **大图舒适网格（2列）**：
   - 突出海报高清封面质感，一屏呈现 4~6 部，适合大屏手机及平板；
3. **微缩书架网格（4列）**：
   - 极高信息密度，适合资深剧迷海量翻阅；
4. **图文列表流（单列）**：
   - 左侧海报封面，右侧结构化展示剧名、题材标签、总集数、主演与剧情概要。

### 3.3 高品质双模主题引擎
杜绝高饱和度与廉价渐变，采用高端工业流媒体色彩规范：
1. **黑曜石深色模式（默认）**：
   - 页面背景、卡片、文本与强调色均引用 `src/styles/design-tokens.css` 的 `--bg`、`--surface`、`--fg`、`--fg-2`、`--accent`；琥珀金为全局唯一主强调色。
   - 播放器音量冰蓝 HUD 只使用 `--player-vol-accent`，不作为全局第二主强调色；具体色值以 Token 正本为准，禁止在业务样式中写裸 Hex。
   - OLED 省电与对比度效果须以真机/实际组合验证，不作无条件承诺。
2. **象牙纯白浅色模式**：
   - 背景主基色：`#F5F6FA` 象牙浅灰白；
   - 表面卡片色：`#FFFFFF`；
   - 文字层级：主标题 `#0F172A`，副文本 `#64748B`；
   - 优势：户外强光与日间环境高对比度清晰易读。
3. **控制机制**：支持【自动跟随系统】、【强制浅色】、【强制深色】三态切换。

## 四、 移动端原生体验与播放器规范

### 4.1 真 Edge-to-Edge 边到边沉浸视界
- **系统层适配**：Android 壳启用 `WindowCompat.setDecorFitsSystemWindows(window, false)`，状态栏与底部手势导航条彻底透明化；
- **刘海屏与挖孔适配**：配置 `LAYOUT_IN_DISPLAY_CUTOUT_MODE_SHORT_EDGES`，视频全屏拉伸至物理硬件最边缘；
- **安全边距防护**：通过 CSS `env(safe-area-inset-top)` 与 `env(safe-area-inset-bottom)` 动态避让控制面板交互按钮，杜绝按钮与状态栏图标打架重叠。

### 4.2 现代流媒体双侧滑动手势与交互
全屏播放模式下全面接管触摸事件：
1. **左侧垂直滑动**：
   - 调节**当前窗口亮度**（0% ~ 100%）；
   - 左侧 0%～48% 触发暖阳亮度 HUD；Web 无原生能力须明确受限；
2. **右侧垂直滑动**：
   - 调节**系统/媒体音量**（0% ~ 100%）；
   - 右侧 52%～100% 触发冰蓝音量 HUD；Web 仅媒体音量，中间保留区不触发；
3. **左右双击手势**：
   - 屏幕左半区双击：快退 10 秒；
   - 屏幕右半区双击：快进 10 秒；
   - 伴随涟漪波纹与“快退10秒 / 快进10秒”动态微交互；
4. **全屏误触锁**：
   - 提供全屏物理锁定按钮，开启后锁定全部手势与交互面板，专为躺卧追剧设计；
5. **睡眠定时自动关闭**：
   - 播放面板工具箱快速呼出定时浮层：`[ 关闭 / 15分钟 / 30分钟 / 60分钟 / 播完本集关闭 / 播完本剧关闭 ]`；

### 4.2.1 底部主导航架构（三轨 v2 定义）
底栏3键【精选/追剧/我的】，搜索为全屏 Overlay（保留历史及三榜）；分享仅播放器内，海报无分享按钮。追剧页正在追→同类好剧→往期完播，推荐有独立可读可点空间；公开追剧/断点真实持久化。缓存管理收纳“我的”，不设独立主页、不挤占推荐区。

### 4.3 独立系统设置中枢（我的 Tab）
设置模块位于底栏【我的】，直通 Android 底层能力：
1. **后台播放总开关**：允许用户切回桌面或微信查收消息时，音频在后台持续流畅播放；
2. **息屏常驻播放（ForegroundService）**：
   - 用户轻按电源键熄灭屏幕后，系统拉起前台保活服务与通知栏控制器；
   - 锁屏界面展示当前剧集名与播放/暂停控制按钮；
3. **来电自动感知（TelephonyManager 广播监听）**：
   - 手机来电呼入（`CALL_STATE_RINGING`）瞬间自动暂停播放并释放音频焦点；
   - 通话结束（`CALL_STATE_IDLE`）后，仅当来电前正在播放、期间用户没有主动暂停/切换内容且音频焦点允许时才自动从记录进度恢复；否则保持暂停；
4. **卡密核销入口**：用户直接粘贴卡密，一键兑换并实时展示到期时间与授权等级；
5. **OTA 版本检测**：一键请求 `/api/version` 获取新版变更日志与更新直链。

## 五、 极简短剧分享与裂变获客闭环

### 5.1 核心原则：零废话、点开即播、播完截流
产品采用“先看单集，再选择是否下载安装”的策略；转化率须通过实际埋点验证，原有“低于 2%”说法无可核查样本，非当前验收目标。

### 5.2 分享短链与协议
- **分享短链格式**：`https://play.prismos.org/s/<drama_id>?ep=<ep_num>&ref=<invite_code>`
- **参数说明**：
  - `drama_id`：短剧内部唯一脱敏 ID；
  - `ep`：分享的具体第 N 集（默认从第 1 集开始）；
  - `ref`：分享者的设备邀请识别码（用于后续裂变赠送时长归因）。
- **合规绝对红线**：仅限【短剧精选】、【院线电影】、【热血动漫】、【人文纪录】频道内容可生成分享链接；**【个人探索】频道内容前端物理剔除分享入口，云端网关严格禁止解析和分发，杜绝域名封禁风险**。

### 5.3 落地页极简体验流程
1. **进入单集播放页**：好友在微信、QQ 或手机浏览器中点击 `/s/:drama_id` 短链，页面直接载入有效公开分集，不展示注册或下载前置页；自动播放被浏览器策略禁止时呈现清晰的单次点击播放入口，不把自动播放成功率写成绝对承诺；
2. **免干扰沉浸体验**：播放过程中不出现任何阻断弹窗，保障用户完整畅看当前单集；
3. **播完瞬间截流（黄金转化节点）**：
   - 当该集视频播放到达末尾触发 `ended` 事件瞬间，播放器画面柔和淡出；
   - 居中弹出半透明卡片：
     ```text
     [ 视频播放完毕提示图标 ]
     本集已播放完毕
     追看后续精彩全集，请下载【光影Play】
     [ 下载光影Play，了解后续内容 ]
     ```
   - 用户点击下载按钮进入 `/dl`；本期仅在已发布 APK 时展示 Android 安装包入口，其他平台不展示不存在的产物。

### 5.4 路由职责划分（两条链路行为必须区分清楚）
- **`/s/:drama_id`（剧目分享）**：无论来自微信、QQ 还是系统浏览器，**一律直接渲染当前单集播放页**，不做自动微信跳出、不插入任何前置页；仅允许用户手动点击下载触发浏览器打开辅助蒙层。微信内自动播放受平台策略限制时，由用户点按一次“播放本集”兜底，不跳转、不要求换浏览器；
- **`/dl`（软件下载引导）**：才承担微信环境下的下载指引（不承诺规避平台限制）——
  - 请求头 `User-Agent` 含 `MicroMessenger`：返回轻量合规引导页，提示“点击右上角，选择在浏览器中打开”；
  - Android 浏览器：引导至 `/dl/latest/android`（R2 最新 `.apk`）；
  - Windows 浏览器：提示当前仅提供 Android 客户端，不出现无产物的 PC 下载按钮；
  - `/dl/latest/android` 为本期固定直链，302 至已发布且校验的 R2 APK；PC 路由暂不提供，需等桌面端具备真实构建与验证后另立契约。
- **口径唯一性**：分享剧目走 `/s`、下载安装走 `/dl`，两者互不承担对方职责；对应契约见 `docs/03-contracts/openapi.yaml`。

### 5.5 邀请裂变 D1 归因闭环
`ref` 在 `/s` 与 `/dl` 链路内可传递，但普通网页下载 APK 后不能自动保证进入 App。首次兑换时仅由用户主动输入邀请码（或以后经过真机证实的安装归因机制）提交 `inviteRef`；有可信归因、非自邀且受邀设备首次成功核销时，D1 唯一结算并为邀请人延长 3 天。没有归因证据不结算，也不得公开承诺每次点击分享都自动奖励。

### 5.6 内容准入与发布控制（本期范围界定）
- **工程边界**：遵照 Master 2026-10-01 裁决（M-1），本期作为私域技术终端，工程侧不设 `license_source` 与 `license_expires_at` 授权准入数据库字段与代码强卡逻辑，合规风险由运营与法务域承担；
- **上架与撤片机制**：`content_items` 默认处于未发布态（`enabled = 0, shareable = 0`），由运营端确认后显式置 `enabled = 1` 发布上架；
- **撤片与下架响应**：内容支持按 `content_id` 快速下架（置 `enabled = 0`），下架后列表、详情、分集解析与分享 `/s` 立即不再对外提供；
- **私密内容零分享**：私密频道剧目 `shareable` 恒为 0，云端禁止分享。

## 六、 云端动态驱动的软性提醒与卡密商业闭环

### 6.1 商业策略100%云端动态化（拒绝写死在客户端）
为了适应不同发展阶段的市场策略，**所有的提醒频率、打赏金额、卡密展示档位与文案，一律由 Cloudflare 边缘接口（`GET /api/config/monetization`）动态下发，客户端严禁写死任何价格或周期**：
- **冷启动初期策略（0 ~ 500 付费用户阶段）**：
  - **废弃月卡**：避免每月续费的高摩擦流失；
  - **暂隐年卡**：初期仅主推极具性价比的 **【季卡 ¥9.9（90天免打扰畅看）】**，以及随心小额打赏（如 ¥6.6）；
  - 待累积 300~500 种子付费用户、验证长线稳定性后，只需修改 Cloudflare KV 配置，即可空中无感上线【年卡】或调整梯度价格，客户端无需发版。
- **动态渐进式软提醒机制（老板打赏心理学）**：
  - 计时口径：严格按客户端本地累积的**真实视频播放秒数（`watch_seconds_total`）**计算；
  - 提醒阶段阈值和间隔仅取有效云端配置，不将历史示例数字作为默认值；缺配置关闭提醒。按实际播放经过时间累计，非position/seek/假duration，暂停缓冲不计、倍速不按媒体位移放大；仅切集自然间隙触发并可关闭；
  - 话术身段：云端动态下发诚恳、接地气的“给老板敬茶/独立作者求口粮”文案，并**始终保留【下次一定，继续看剧】可关闭按钮**，绝不强行锁死阻断用户。

### 6.2 预制卡密机制与宽松家庭共享裂变
彻底告别传统“用户发送设备识别码，运营人员在电脑端运行脚本算号”的人工模式。
- **发卡方机制**：发卡管理员通过受控批量导入流程生成指定档位卡密池；导入须校验唯一性、档位、有效期和总量，使用安全随机数，不在客户端生成卡密，不把卡密明文写入普通日志。控制台或 CLI 是可选实施入口，真实入口须在阶段 1 验证。
- **卡密格式规范**：本期保留 `GY-Q90D-A7F2-8899` 等历史实例；`GY-` 后第二段 4～5 位且首字符为 Q/A/B/Y/S，随后两段各 4 位大写字母数字。格式仅负责解析，真实档位和期限以 D1 卡密记录为准；发卡端与兑换端使用 OpenAPI 的同一校验表达式。
- **卡密档位唯一定义（全工程以此为准，展示哪些档位由云端动态决定）**：

| 档位 | 名称 | 时长 | 公开权益 | 个人探索权限 | 初期是否公开展示 |
| :---: | :--- | :--- | :--- | :---: | :---: |
| `Q` | 季度畅享卡 | 90 天 | 四公开频道免打扰畅看、多源极速专线 | 无 | 是（初期唯一主推，¥9.9） |
| `A` | 普通激活卡（历史兼容） | 30 天 | 同 `Q`，用于旧卡密延续 | 无 | 否 |
| `B` | 高级全源卡 | 视发卡批次 | 四公开频道 + 高源优先 | 有 | 否（暂隐，权限保留） |
| `Y` | 年度尊享卡 | 365 天 | 四公开频道 + 高源优先 | 有 | 否（暂隐，权限保留） |
| `S` | 极客纪念卡 | 永久（`expires_at = -1`） | 全权益 | 有 | 否（仅内部赠予，不对外售卖） |

> 说明：只有 `B / Y / S` 具备【个人探索】准入资格；`Q / A` **不涉及**个人探索，这既是商业分层，也是合规边界。
> 是否公开展示某档位由云端商业配置动态控制，客户端严禁写死任何价格、档位或时长。
- **合规宣传红线**：所有卡密介绍仅宣传“免打扰纯净观影、多源极速专线、支持独立作者维护”，**严禁在任何公开界面将“个人探索（私密内容）”作为售卡权益宣传**。
- **宽松共享与裂变哲学（Master 商业定案）**：
  - 前期不搞严苛的单设备锁死，**默认允许最多 10 台设备共享激活**（完全满足用户给父母、伴侣、密友共享使用），以此作为推动口碑裂变的主力引擎；
  - 鉴于卡密自带有效时限（到期即止），共享范围越广，到期后沉淀的忠实付费转化群体越多；
  - **异常风控底线（口径必须可达）**：成功绑定上限严格为 10 台，第 11 台起直接拒绝。因此“绑定数超过 20~30 台”在本机制下**不可能出现**，异常判定改为统计**被拒绝的、彼此不同的新设备数**（`rejected_distinct_count`）：当同一卡密累计被 **超过 20 个不同设备**尝试绑定时，自动标记 `is_abnormal = 1`，便于后台审计与处理倒卖黑灰产。
  - **幂等与并发口径**：同一设备重复提交同一卡密不得重复计数、不得报错，返回与首次一致的成功结果；第 10 与第 11 台并发提交时，最终成功绑定数必须恰好为 10，超出者收到 `COUPON_DEVICE_LIMIT_EXCEEDED`。

### 6.3 D1 数据库核销与绑定流程
1. **客户端提交**：用户在 Android 设置中心输入卡密，客户端首次安装生成 8 位大写字母数字随机标识（前缀 `GY-`）并在系统级安全存储中持久化作为 `deviceId`，POST 请求 `/api/redeem`；重装可能改变标识、恶意客户端可伪造，不能宣称可靠硬件唯一性。
2. **核销并发裁决（禁止先读计数再无条件写入）**：
   - 验证卡密存在且 `status` 为 `UNUSED/ACTIVE`，不得仅以“不等于 REVOKED”判定有效；
   - 若该 `deviceId` 已绑定此卡密 → 走幂等分支，`device_count` 不变，在线授权以当前卡密/设备状态计算，不盲目重放过期令牌；
   - 新设备按 `status IN ('UNUSED','ACTIVE') AND device_count < max_devices` 条件更新并与设备/绑定流水组成同一原子写入单元；条件未命中时不得落绑定行。D1 batch 回滚能防部分提交，但高并发下跨请求的一致性仍需阶段 1 用真实 D1 并发样本验证；未通过不得宣称第 11 台严格拒绝已实现。
   - 在 `devices` 表写入/更新该设备的授权等级 `tier` 与计算后的 `expires_at`；
   - 若为超限拒绝，则将该 `deviceId` 记入 `coupon_rejected_devices`（同一设备只记一次），当不同被拒设备数超过 20 时置 `is_abnormal = 1`；
3. **下发 JWT 凭证**：服务端以**非对称私钥**签发 JWT，Payload 包含 `deviceId`、`tier`、`exp`、`kid`；客户端仅持有公钥用于离线校验签名，客户端存储使用系统级安全存储（Android Keystore 支持的加密存储），不使用明文偏好文件。

### 6.4 离线容灾认证机制
- **能力边界（不得夸大）**：最长 **14 天**的离线能力是**授权状态可离线验证**——客户端用内置公钥校验本地 JWT 的签名、`exp` 与设备绑定，在断网时仍能正确显示授权档位与到期时间，并在未来另行实现有明确离线缓存许可的非私密媒体功能时才考虑离线播放；**本期只离线展示公开目录快照，不提供视频文件缓存与离线播放**；
- **明确不承诺**：本期不提供视频离线下载及任何断网播放；播放源由云端解析，无网无法解析新的分集地址；公开目录与缩略图快照可离线浏览，但不得当作当前可播证明；
- **私密内容例外**：个人探索内容严禁写入磁盘缓存，因此任何情况下都不参与离线播放；
- **防篡改与续期**：以最后成功联网时间和可靠本地时间记录约束 14 天窗口；若本地时钟显著回拨且无法可靠证明当前时间，则停止离线授权并提示联网。设备重新联网后向 `GET /api/device/ping` 校验撤销状态并取得新凭证；云端撤销无法即时通知完全离线设备，该已知窗口须在交付时披露。

## 七、 核心功能优先级与 RICE 评分矩阵

遵循 RICE 科学评估模型进行功能优先级排定：
- **Reach (到达率)**：1-10，每季度受影响的用户比例（10=100% 用户）；
- **Impact (影响力)**：0.25=微小，0.5=小，1=中，2=大，3=巨大；
- **Confidence (信心度)**：50%=直觉猜测，80%=有行业基线，100%=有充分数据或成熟验证；
- **Effort (投入成本)**：人月估算（1=极小/半天，10=超大型）。
- **公式**：$\text{Score} = \frac{\text{Reach} \times \text{Impact} \times \text{Confidence}}{\text{Effort}}$

> 说明：RICE 得分用于辅助排序，**最终取舍以「优先级」列为准**（部分 P0 因存在硬前置依赖而排在分数更高的项之前）。表中 Confidence 取值属经验估计，未经数据验证，不作为交付承诺。

| 模块序号 | 功能特性描述 | Reach (1-10) | Impact (0.25-3) | Confidence (50%-100%) | Effort (1-10) | RICE 得分 | 优先级 | MVP范围 |
| :---: | :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **F-01** | **去平台化四公开频道流媒体浏览** | 10 | 3.0 | 100% | 2.5 | **12.00** | P0 | **MVP必须** |
| **F-02** | **双滑手势播放器(左亮度/右音量/双击快进退)** | 10 | 2.5 | 100% | 2.0 | **12.50** | P0 | **MVP必须** |
| **F-03** | **预制卡密云端自动核销与JWT离线容灾** | 10 | 3.0 | 90% | 2.5 | **10.80** | P0 | **MVP必须** |
| **F-04** | **极简短剧分享(点开即播H5+播完截流下载)** | 8 | 3.0 | 90% | 2.0 | **10.80** | P0 | **MVP必须** |

## 八、 明确不做清单 (Out-of-Scope 边界红线)

为确保 MVP 周期聚焦与交付质量，严守以下业务与工程边界，当前阶段一律坚决不予研发：

1. **坚决不做用户账号体系与手机号/密码注册登录**：
   - 拒绝短信验证码、邮箱验证、密码找回流程，全面推行无感 DeviceID + 卡密认证模式，降低用户心理防线与合规风险；
2. **坚决不做应用内第三方在线支付 SDK（微信/支付宝商户直连）**：
   - 不在 App 内部集成微信支付或支付宝原生 SDK，规避应用市场内购审查与资质下架风险，所有商业流转完全依托预制卡密发放与兑换；
3. **坚决不做社交、评论区与滚动弹幕互动系统**：
   - 坚决杜绝 UGC 内容审核风险，剔除弹幕、点赞评论、私信等社交负重，维持纯粹的个人沉浸观影工具属性；
4. **坚决不做重型服务端集中式实时视频重编排转码与自建视频 CDN**：
   - 依赖原生播放器硬解与同源受控代理 `play.prismos.org/proxy/*` 分发，拒绝在云端架设 GPU/CPU 转码集群（旧版 `juku_arm64` 本地 Go 微核方案已永久废弃，不得回退）；
5. **坚决不做花哨的开屏广告、横幅广告与信息流插屏商业变现**：
   - 全链路严禁植入任何广告联盟 SDK，保持产品绝对纯净。

## 九、 核心验收标准清单 (AC-01 ~ AC-15；新增 AC-16 ~ AC-18 见 §12.5，AC-19 ~ AC-30 见 §12.6)

> 验收标准统一遵循严格 EARS (Easy Approach to Requirements Syntax) 语法模式：  
> `[While 条件] [When 事件] [Where 位置] [If 前置] 系统必须/应该 [特定行为/状态响应]`

### AC-01：四公开频道初始加载与默认定位
- **EARS 描述**：**When** 用户完成应用启动并进入主视界，**系统必须** 默认展示综合首页；若存在上次同步的四公开频道快照，先渲染本地快照并后台增量同步，若无则请求云端公开快照。后续固定公开导航顺序、综合候选和推荐配额依 `HOME-PLAYER-REPAIR-SPEC-AND-PLAN.md` HP-04/05 执行，不新增云频道。首屏首帧渲染耗时以真机冷启动实测为准（目标 ≤1.2s，须记录机型与网络条件，未实测前不得写为已验证结论）。

### AC-02：个人探索频道双重物理隐形
- **EARS 描述**：**Where** 在客户端任何列表、分类选择器、DOM 树与接口响应中，**If** 当前设备未同时满足「有效 B/Y/S 高级授权」与「本次会话手动开启」两个条件，**系统必须** 物理剔除【个人探索】节点与对应数据，不得展示锁定状态、灰度图标或密码输入弹窗；
- **补充约束**：开启状态仅存内存，冷启动、完全退出或会话结束即失效；未开启时 `/api/channels`、`/api/sources` 与内容接口均不得返回私密节点；**If** 请求的分享链接指向私密内容或未知剧目，边缘网关必须返回 404。

### AC-03：首屏黄金位断点续播
- **EARS 描述**：**While** 本地数据库存在有效的观看历史记录，**When** 用户进入主页顶层视界，**系统必须** 在首屏最上方以悬浮卡片展示最近观看的剧名、集数与精确秒级时间戳；**When** 用户点击该卡片，**系统必须** 无缝拉起播放内核并从历史时间戳起播（起播耗时目标 ≤800ms，须真机实测记录，未实测不得写为已验证结论）。

### AC-04：四模海报排版无抖动切换
- **EARS 描述**：**When** 用户点击顶栏排版切换图标并在窄屏（< 768px）【3列中图】、【2列大图】、【4列书架】、【单列图文】之间循环切换时，**系统必须** 完成网格重绘且切换过程不出现整屏白屏或可感知卡顿（以真机评审为准），并立即将所选排版枚举写入本地持久化存储；平板与桌面（≥768px）依据 `design-tokens.json` 规则自适应扩展列数。

### AC-05：日夜双模深浅主题切换
- **EARS 描述**：**When** 用户在设置中切换主题或系统深色模式发生变更，**系统必须** 瞬间完成全局 CSS 变量重置；在深色模式下背景色必须严格为 `#080A10`，在浅色模式下背景色必须严格为 `#F5F6FA`，且严禁出现任何紫色到粉色的高饱和渐变。

### AC-06：左侧垂直手势调节窗口亮度
- **EARS 描述**：**While** 全屏播放，**When** 在左侧 `0% ~ 48%` 垂直滑动，**系统必须** 通过原生 Bridge 调节当前窗口亮度并显示暖阳亮度 HUD；Web 无原生能力须明确受限，不以遮罩冒充。

### AC-07：右侧垂直手势调节音量
- **EARS 描述**：**While** 全屏播放，**When** 在右侧 `52% ~ 100%` 垂直滑动，**系统必须** 线性调节音量并显示冰蓝 HUD；中央 `48% ~ 52%` 保留区不触发。
- **平台边界**：Android 系统音量须原生 Bridge，Web/H5 仅播放器媒体音量，不声称可改系统音量。

### AC-08：左右双击快退与快进
- **EARS 描述**：**While** 视频正在播放过程中，**When** 用户双击左侧区域，**系统必须** 向后跳跃 10 秒并继续播放；**When** 用户双击右侧区域，**系统必须** 向前跳跃 10 秒并继续播放，交互响应即时、不出现可感知延迟（以真机评审为准）。

### AC-09：快速睡眠定时自动关闭
- **EARS 描述**：**When** 用户在播放控制面板中设定定时关闭倒计时（例如 15 分钟），**While** 倒计时进入最后 3 秒，**系统必须** 开始平滑淡出音量并在倒计时归零瞬间完成淡出、暂停播放，同时安全停止后台常驻服务并释放播放句柄（渐隐时长口径全工程统一为「归零前 3 秒开始、归零时结束」）。

### AC-10：锁屏与后台常驻播放
- **EARS 描述**：**While** 设置中开启“允许后台/息屏播放”选项，**When** 用户按下设备电源键锁屏或切回手机系统桌面，**系统必须** 保持音频播放不间断，并调用原生 `ForegroundService` 在通知栏和锁屏中心展示包含剧集标题与播放/暂停控制的原生卡片。

### AC-11：系统来电自动暂停与恢复
- **EARS 描述**：**When** Android 系统广播接收器监听到来电呼入状态（`TelephonyManager.CALL_STATE_RINGING`），**系统必须** 立即暂停当前视频流并记录断点；**When** 电话挂断并恢复空闲状态（`CALL_STATE_IDLE`），**若** 来电前正在播放、通话期间用户未主动暂停或切换内容且音频焦点已恢复，**系统应该** 自动从记录断点恢复播放；否则保持暂停，不强行抢回音频焦点。

### AC-12：短剧分享落地页极简点开即播
- **EARS 描述**：**When** 外部访客通过手机浏览器访问短链 `https://play.prismos.org/s/<drama_id>?ep=<ep>&ref=<ref>`，**系统必须** 在返回的轻量 H5 容器中跳过一切产品介绍页，直接载入 `ep` 对应分集并自动尝试播放视频流。

### AC-13：视频播放完毕精准截流转化
- **EARS 描述**：**While** 外部访客在落地页观看单集短剧，**When** 视频内核分发 `ended` 播放结束事件瞬间，**系统必须** 自动平滑淡出播放控件，并在画面中心浮现提示卡：“本集已播放完毕，如果继续看，请下载【光影Play】”与安装包直链下载按钮。

### AC-14：预制卡密原子核销与宽松家庭共享
- **EARS 描述**：**When** Android 客户端向 `/api/redeem` 提交卡密与设备安装标识，**If** 该设备已绑定过此卡密且卡密/设备当前仍有效，**系统必须** 幂等返回当前授权且不重复计数；**If** 为新设备且当前 `device_count < max_devices`（默认 10 台），**系统必须** 通过单次条件写入建立绑定流水、累加计数，并下发带非对称签名的 JWT 与到期时间戳；**If** 新设备使绑定数将超过 `max_devices`（即第 11 台起），**系统必须** 拒绝绑定并返回 `COUPON_DEVICE_LIMIT_EXCEEDED`；**If** 被拒绝的彼此不同设备数累计超过 20，**系统必须** 自动将卡密标记为 `is_abnormal = 1`。

### AC-15：离线授权可验证（非离线可看任意视频）
- **EARS 描述**：**While** 设备处于无网络状态，**When** 用户启动应用，**系统必须** 基于本地安全存储的 JWT 与内置公钥完成签名、`exp` 与设备绑定的离线校验；**If** 距最后一次成功联网校验在 14 天以内且授权未过期，**系统必须** 正确显示授权档位与有效期，并可浏览已缓存的公开目录和海报；**When** 用户请求播放，**系统必须** 明确提示需要网络，不得假装可播放；**系统不得** 在离线状态下播放任何个人探索内容。

## 十二、 本期三层闭环补充（2026-10-01 决策）

> 本节修订此前“AI 与向量均属后续”的笼统范围声明。**本期**将 AI 用于已配置来源的元数据加工、语义搜索与同类推荐；AI 角色扮演仍属 v2.1+。Cloudflare 账号 Workers Free/Paid 及实际 AI 用量尚未核实；不自动开通付费能力，超额时降级但不得停止基础目录与词法搜索。前述 F-01 的“相同剧名自动去重”仅指候选识别：同名绝不单独触发归并。

### 12.1 客户端程序：先看公开缓存，再增量联网
- Android 为本期唯一安装包交付平台；公开 H5 分享页为另一交付入口。Windows 下载安装包、`/dl/latest/pc` 及桌面客户端移入后续，不展示虚假 PC 下载按钮。
- 四个公开频道持久化频道、目录分页、详情摘要、缩略海报、公开搜索热词及非私密断点；设备启动先呈现已缓存快照，再通过版本/游标获取变更集；同修订快照完整到齐才原子替换，进程中断或写失败保留上个完整快照。图片按稳定资源 ID + 版本指纹更新；本期公开海报缓存默认上限 512 MiB、目录元数据 20 MiB，LRU 淘汰海报和已浏览旧分页（不淘汰续播进度与安全凭据）；存储失败仍可在线浏览。用户主动清除缓存不删除凭证/进度，端侧具体持久层和 WebView 的私密磁盘缓存抑制须真机验证。
- 缓存目录与海报**不等于**缓存视频。当前 MVP 不承诺离线视频播放；断网时公开快照可浏览，点播放提示联网。14 天仅用于离线验证授权。个人探索的标题、封面、检索词、列表、进度、媒体、预加载与系统备份均不得进入应用控制的持久存储；退出立即清理应用可控内存引用。
- 搜索框覆盖输入补全、搜索结果、类型/题材筛选、零结果与网络失败；在线完整搜索本期按内容 ID 去重，翻页期间索引变更时可能重复/遗漏，不承诺跨页历史快照；离线仅在缓存的公开目录内搜索，须标注结果可能过时。补全处理中文输入法合成、过期请求取消、键盘/读屏无障碍，不把云端结果写入个人探索的持久缓存。

### 12.2 云端设计：已配置来源的自动生产和混合搜索
- 来源仅由管理员配置并校验接入范围，不自动发现全网；Adapter 增量读取目录、详情与分集元数据，保存来源 ID、采集批次、游标及原始记录摘要。Cron 触发分批任务；抓取、清洗、AI 丰富、归并、发布和源健康巡检分开记录；单条失败自动重试最多 3 次，额度不足保留待处理并在下一个可用额度窗口继续，超过上限自动隔离且保留原因，新修订可重新进入，不覆盖已发布的正确元数据。
- Workers AI 生成候选标签、剧情主题及别名并对变化内容生成 BGE-M3 向量；规则验证输出属于受控词表且结构完整。Vectorize 用于语义与同类候选，不是权威发布表。同来源稳定 ID 可判同源重复；跨来源只有可信的跨源作品映射等强证据才允许自动归并；仅同名、图片相似或向量相近不得自动合并，低证据候选保持独立并待后续证据自动重算，禁止错并串集。
- 完整搜索采用剧名/别名/拼音及题材词法召回、有限候选纠错、自然语言语义召回与标签/向量同类推荐；精确命中优先。输入补全不对每次按键调用生成模型；AI/向量不可用时退化为词法搜索，标注降级但不伪造语义结果。用户提交完整查询后才考虑向量化；所有召回的内容 ID 必须回 D1 复核当前上架、有效期及访问权限。
- 搜索与分类质量由固定样本集衡量：精确名称、别名、中文短词、拼音/多音字、误字、剧情描述、同名异剧、无结果、撤片及无权个人探索；性能数字只有在样本规模、机型/网络和实际额度明确后设定。
- D1 为权威内容状态；KV 仅缓存公开配置与目录加速，Vectorize 异步索引。撤片先使 D1 拒绝新的详情、取流与分享，然后异步清理搜索、向量和客户端目录；断网旧快照无法远程即时擦除。AI 免费配额不足时新内容加工排队、旧目录可用；是否启用付费另行授权。

### 12.3 传输与同步：三种不同的数据新鲜度
- 公开频道/目录提供版本快照及分页变更（新增、更新、删除墓碑），客户端以单一游标顺序应用并在缺页/游标过期时重拉快照；图片 ETag/内容指纹决定复用，禁止每次冷启动重拉全部海报。
- 私密响应和媒体设置禁止持久缓存的响应头，服务端按有效 B/Y/S JWT + 当前会话凭据双重校验；未获准的私密 ID 在详情、播放、搜索、分享与代理中一律表现为不存在，不以 403 泄露分类；频道/搜索返回空集且无私密元数据。只有公开目录可返回允许客户端持久化的缓存提示。
- 播放源选择由边缘服务完成：播放接口只返回**单个**同源短时代理句柄，故障时客户端重新请求解析并保持分集与进度，不要求客户端掌握真实源或对多源并发竞速；源健康与切换只在授权有效的候选中进行。分享页面只对可分享且分集有效的公开内容服务；`/dl` 本期只提供 Android 下载。
- 在线状态变化由 D1 权威判断，不依赖 KV 或向量的即时一致性。云端配额/模型故障不影响静态目录、词法搜索、既有取流认证；本地缓存仅决定快显，不能授权新的媒体会话。

### 12.4 共享数据定义与失效边界
- `[今日爆火]` 只在有同口径的公开播放事件时按过去 24 小时有效起播设备去重排名；暂无可用事件时隐藏榜单，不展示伪造顺序。`[最新上线]` 以 D1 首次公开发布时间倒序；无发布时间不可标记最新。`[偏好推荐]` 本期仅用设备本地公开观看历史与已存公开标签计算，历史为空时退回“探索同类”或隐藏，不上传个人探索事件。胶囊实际显示以云端可用能力为准，而非永远占位。
- 海报与画质标识只基于已存在并可展示的真实字段；缺可信清晰度不展示“4K/超清”。公开目录快照不作为在线许可凭证，撤片在线接口先拒绝，再由增量变更清理本机目录/海报；断网时旧快照可能可见，重新联网前不得允许媒体播放。
- 分享邀请参数 `ref` 在普通浏览器下载 APK 后**无法天然跨安装传入 App**。本期可靠归因路径是用户显式输入邀请码，或后续经真机验证的 Android 安装归因机制；无法证明归因时不结算三天奖励，不能仅凭落地页 URL 认定首次兑换。涉及该奖励的公开承诺须待归因链实测通过。

### 12.5 本期新增可验收结果
