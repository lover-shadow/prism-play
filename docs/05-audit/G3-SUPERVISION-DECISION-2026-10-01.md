总包团队对安全边界的克制极其专业（“自造公钥等于自造合法签名，故保持 fail-closed 到 no-pinned-key”）。

  ```json

    "key_ops": ["verify"],
    "ext": true,
    "alg": "EdDSA"

  ```
- **回填排期裁定**：总包已将单测建立在“未注入公钥则安全沉默 fail-closed”的防御性逻辑上。**本公钥正式定于【阶段 4 生产打包/发版装配】环节填入 `src/core/identity/offline-grant.ts` 的 `PINNED_VERIFICATION_KEYS['p2026']`**，私钥由监理方注入 Cloudflare 线上 Secrets，实现真实云端签发与客户端离线验签闭环。

### 2. B-2 裁定：SPEC §6.1 目录分块 JSON 口径正式采纳
- **裁定结论**：**完全采纳总包的轻量分块 JSON 实现（`cache/catalog/r{rev}/c{n}.json`）**！
- **理由**：在移动端，将云端分页 JSON 直接落地分块文件，比在端侧再维护一个只读 SQLite 库更轻量、读取更快、无并发锁冲突且便于按版本目录一键物理删除；
- **监理动作**：监理方已修改 `SPEC-v2.0.md §6.1`，将表述纠偏为“本地文件系统 (`cache/posters/` + `cache/catalog/r{rev}/`)”，总包无需改动任何代码，口径完全一致。

### 3. B-3 裁定：追认冷装机 `deviceId` 缺失时的回落生成
- **裁定结论**：**正式追认并高度嘉奖！**
- **理由**：冷装新机本地必然无 `deviceId`，若无此自愈回落则无法发起卡密核销，此逻辑完全符合 PRD §6.3 契约意图。

### 4. B-4 裁定：`OFFLINE_GRACE_SECONDS` 保持对账测试
- **裁定结论**：**保持现状**。两端各定义一次并通过已有对账测试钉死为 14 天（`14 * 24 * 60 * 60`），解除了跨模块强引用耦合，且逻辑绝对单源。

### 5. 关于“60-main-boot 的 Web 宿主退化断言”证明力审查
- **审查结论**：**证明力充分且设计极其优美！**
