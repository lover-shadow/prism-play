## 二、 二级分类主流化设计哲学与标准对照 (Taxonomy)

### 1. 核心设计原则（去伪存真 · 回归题材）
1. **彻底剥离“伪分类”**：
   - 严禁将“今日爆火”、“偏好推荐”、“最新上线”等运营排序概念作为二级胶囊展示；
   - 客户端胶囊栏首项天然锁定「全部」（由客户端自动补齐），瀑布流默认按 `updated_at DESC` 最新更新时间自然排列，无需占用胶囊栏宝贵的横向视口。
2. **纯粹题材属性（Genre-Only）**：
   - 二级分类 100% 对应内容自身的题材属性；
   - 统一收敛为 **2 个汉字**，各大频道精简至 **5~6 个核心赛道**，彻底消除“华语大片/好莱坞”等地域混淆。

## 三、 站源纯净度与流媒体安全链路 (Streaming Architecture)

### 1. 验证源选择依据（源自成熟工程积淀）
工程继承并复用了在 `guoguo-juku` 与 `guangying-duanju` 长期验证过的纯净采集源，技术优势如下：
- **画质规格**：原生 **1080×1920 (竖屏短剧)** 或 **1920×1080 (横屏影视)** 超清 HLS；
- **纯净安全**：逐行扫描 `.m3u8` 清单与 `.ts` 分片，**零博彩插播、零跑马灯字幕、零黑产水印切片**；
- **网络合规**：上游自带开放 CORS（`Access-Control-Allow-Origin: *`），直连不防盗链。

### 2. 受控媒体代理与防 SSRF 白名单
依据 SPEC §5 与《Cloudflare 边缘云脑白皮书》，客户端永不接触真实上游地址：
- 客户端通过 `GET /api/episodes/:id/playback` 获取加密签名句柄；
- 请求落到 `GET /proxy/media/:handle?exp=&sig=` 时，边缘实时比对 `source_providers` 白名单；
- 已登记生效的安全上游节点：

## 四、 全文检索与增量同步更新机制

### 1. FTS5 中文单双字切词（`public_search_fts`）
由于 SQLite 内置 `unicode61` 分词器不会主动对连续汉字切词，入库时必须由预处理程序写入分词词元：
- **切词算法**：以“银行取养老金”为例，写入单字（`银 行 取 养 老 金`）+ 相邻双字（`银行 行取 取养 养老 老金`）+ 全词（`银行取养老金`）；
- **检索效果**：用户输入单个汉字（如“老”）、词组（如“养老”）或剧名全称，均能在 1ms 内精准召回候选。

### 2. 增量变更游标日志（`public_catalog_changes`）
- 每次作品上架或更新，必须在同事务中向 `public_catalog_changes` 写入一条 `operation = 'upsert'` 记录；
- 数据库自动分配自增修订号 `revision`；
- 客户端启动时通过 `/api/catalog/changes?after={lastRevision}` 获取增量变更，实现客户端 0 重载热更新。

## 五、 数据运维手册与更新脚本 (Runbook)

工程根目录内置了端到端全自动化的数据抓取、清洗与写入工具链：

### 1. 核心脚本职责映射
- `edge/scripts/seed-production-content.mjs`：多频道数据抓取与分词算法模块；
- `edge/scripts/seed-runner.mjs`：清洗转换器，生成符合 D1 规范的 `seed-data.sql`；
- `edge/scripts/seed-data.sql`：原子写入批次文件（包含 providers、items、episodes、sources、FTS 与 changes）。

### 2. 如何一键扩充新一批片单 (标准操作工序)
```bash
# 步骤 1：进入边缘目录
cd D:\DEV\prism-play\edge

# 步骤 2：运行抓取与清洗生成器（自动从上游提取并格式化）
"C:/Users/Master/.workbuddy/binaries/node/versions/22.22.2-3/node.exe" scripts/seed-runner.mjs

# 步骤 3：一键将数据灌入远程 Cloudflare D1 数据库
npx wrangler d1 execute prism-play-db --remote --file=scripts/seed-data.sql

# 步骤 4：验证线上数据规模与分类
npx wrangler d1 execute prism-play-db --remote --command "SELECT channel_id, count(*) as count FROM content_items GROUP BY channel_id;"
```
