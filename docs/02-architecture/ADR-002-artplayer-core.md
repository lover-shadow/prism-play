# ADR-002: 采用成熟开源播放器 ArtPlayer.js 作为全手势播放内核

- **状态 (Status)**: Accepted (已采纳)
- **决策日期 (Date)**: 2026-09-30
- **决策者 (Deciders)**: Master_流光逸影 (架构主理人), 大湾区靓仔 (项目总监), 高见远 (首席架构师)

---

## 背景与问题陈述 (Context and Problem Statement)

在流媒体播放终端中，移动端手势交互（左半屏滑动手势调音量、右半屏垂直滑动手势调屏幕亮度、双击 10 秒快进快退、全屏锁定、快速定时关闭）是决定产品是否具备“工业级流媒体质感”的生命线。  
若从零实现播放器状态、触摸交互与 HLS 重试，维护面会扩大；具体代码量与手势兼容性需在集成与真机回归后测量，不以假定行数作为选型证据。

我们需要决定：采用何种开源播放内核来承载播放控制？

---

## 考虑的备选方案 (Considered Options)

1. **从零自研基于原生 HTML5 `<video>` 的播放器**；
2. **Video.js**（老牌国际开源播放器，体积较大，移动端手势插件生态陈旧）；
3. **xgplayer**（字节跳动西瓜视频开源播放器，移动端优化好但样式侵入度高）；
4. **ArtPlayer.js**（国内顶级开源 HTML5 播放器，轻量、丝滑、现代，MIT 协议开源）。

---

## 决策结论 (Decision Outcome)

**选择【ArtPlayer.js】**。

### 核心采纳理由
- **播放器可扩展**：选择 ArtPlayer 承担视频状态、控制台与事件接口；项目自建左右分区手势/HUD、双击跳转与原生音量/亮度桥，不预设这些能力全部开箱即用。
- **HLS 适配**：以 `hls.js` 接入经授权代理流；切源、Range、清单分片鉴权及清晰度能否切换须以真实 HLS 样本验证，不凭格式宣称支持 4K。
- **轻量无侵入**：纯原生 JS，无第三方框架依赖；实际打包增重在集成后以构建产物为准，不在本文中给出未验证的字节数；
- **深度适配 Design Tokens**：播放器控制台、进度条与 HUD 弹层 100% 接入琥珀金（`#E5A93C`）日夜双模 CSS 变量体系。

> **已知边界**：Web 播放器只能控制播放器自身音量；改变系统媒体音量与窗口亮度需要自建原生 Bridge（`AC-06` / `AC-07` 已按平台分别验收）。
