# 《光影Play》（Prism Play）系统重构与架构校准蓝图 (REFACTOR-REBOOT-PLAN.md)

> 本文档为《光影Play》下一阶段工程重构的法定事实依据与执行计划。旨在客观梳理项目的演进脉络、明确当前暴露的缺陷与真实需求、界定云端与外部资源边界，并给出确定性的重构落地方案。本文档仅作客观事实与工程约束陈述，不包含任何主观假设。

---

## 一、 来龙去脉：为什么要进行重构

### 1.1 历史演进路径
1. **第一代 `guoguo-juku`（Go 本地单体）**：
   - 实现了多源直连、实时排行榜单、穿透搜索与局域网 DLNA 投屏；
   - 维护了本地资产库 `data/library.json`（文件体积 22.4 MB，收录 10 个数据源、共计 14,094 部剧目）；
   - 依赖本地 Go 运行时作为常驻代理进程。
2. **第二代 `guangying-duanju`（去 Go、轻量化试验）**：
   - 验证了前端直接消费多源数据、无中心化死库负担的聚合模式；
   - 确立了以“打开即看、全网实时搜索、全网榜单直连”为核心的轻量工具属性。
3. **第三代当前 `prism-play`（Capacitor 7 + TypeScript + Cloudflare Serverless）**：
   - 重构初衷：引入商业化预制卡密核销、多端（手机/TV/PC）断点接力、现代工业级播放器（ArtPlayer）手势体验与统一云端空中调度；
   - 现状：成功跑通了 Android 原生构建（`dev_v2.1.1.1` APK）、日夜双模 Tokens 与卡密核销流程。

### 1.2 当前系统暴露的核心技术断层与客观缺陷
经端到端真机与代码链路核验，当前实现偏离了既定设计目标，具体表现为：

1. **云端 D1 数据库读配额熔断（HTTP 503）**：
   - 云端将 8,874 部全量视频元数据与 FTS5 倒排索引物理写入 D1 关系数据库；
   - 在缺乏有效覆盖缓存的情况下，客户端每次分页浏览或全库打分均触发大批量行读，直接击穿 Cloudflare D1 免费层每日 500 万行读上限，导致全站 API 频繁被云端熔断拦截并报 503；
2. **成熟多源资产严重缺失，退化为单一魔都源**：
   - 历史底库 `library.json` 中的成熟大源（红果 2,188 部、黄果AI 2,263 部、帝果 3,410 部等）未被并轨接入；
   - 现有云端仅接入了 `caiji.moduapi.cc` 单一第三方采集站，片单品质参差不齐，且缺少全网头部热门内容；
3. **短剧精选频道的 AI 短剧实际收录量为 0**：
   - 抓取脚本错误地将 `type_id = 42`（AI 漫剧）全部映射至【热血动漫】（`anime`）频道；
   - 【短剧精选】（`drama`）频道内的 `is_ai = 1` 作品数量为 0；
   - 客户端推荐引擎触发“AI 信号缺席即诚实降级且不贴标”的保护逻辑，导致用户在短剧精选刷新数十页均无法看到任何 AI 剧及【AI精品】角标；
4. **短剧分享落地页（`/s/{drama_id}`）完全无法播放，裂变链路失效**：
   - `edge/src/html/share-page.ts` 中针对 HLS 的探测逻辑规定：若浏览器原生的 `video.canPlayType('application/vnd.apple.mpegurl')` 返回空，则直接执行 `return` 并不加载 `video.src`；
   - 在微信 Android 内置浏览器（X5/TBS 内核）、桌面 Chrome、Edge 及多数安卓系统浏览器中，原生 HLS 探测均返回空，导致页面直接黑屏并报不支持，视频 100% 无法起播；
   - 下载截流卡片被硬编码绑定在视频播放结束的 `ended` 事件上；播放既然无法开始，下载卡片便永远无法展示；
   - 根路径 `https://play.prismos.org/` 返回 404，缺少官方介绍与 APK 统一分发主页；
5. **客户端交互退化，缺少现代流媒体体验**：
   - 首页瀑布流每页展示 20 部作品，触底需要用户手动点击【加载更多】按钮，缺乏 `IntersectionObserver` 自动触底无感续载；
   - 搜索框为静态跳转按钮，缺乏输入即防抖呼出的动态联想浮层（Autocomplete）；
   - 丢失了 `guangying-duanju` 已具备的【全网热播榜/新剧榜/AI榜】专区，以及按状态（已完结/连载中）和按排序（最热/最新）的过滤机制；
6. **未严格履行“去平台化”规范**：
   - 数据链路与源配置中仍直接残留第三方原厂名称，违背了“聚合工具对外只展示统一独立品牌、上游源完全脱敏”的工程纪律。

## 二、 核心需求矩阵：我们需要什么

### 2.1 商业与平台治理需求
1. **统一独立品牌**：
   - 客户端与分享页对外的唯一服务主域为 `play.prismos.org`；
   - 物理抹除所有第三方原厂字眼，线路统一抽象为中性代号（如【线路一 · 极速】、【线路二 · 蓝光】）；
2. **预制卡密原子核销**：
   - 客户端提交设备识别码与卡密，云端 D1 单事务完成核销并绑定（单卡上限 10 台设备），签发 Ed25519 JWT 凭证，支持 14 天离线本地验签；
3. **付费会员多端状态同步（User Sync）**：
   - 仅限有效会员设备可用；
   - 触发时机严格收敛于两个离场节点：**退出播放页/返回时** 与 **应用挂起/即将退出时**；
   - 单次请求合并上报单条观看断点与本地题材偏好得分向量，实现手机、客厅电视（TV）与 PC 跨端续播与喜好继承；
   - 私密探索内容（`is_private = 1`）绝对禁止上报云端同步；
4. **分享裂变与官方门户**：
   - 微信、移动端与 PC 浏览器点开分享短链（`/s/:id`）直接秒播第 1 集；
   - 页面全生命周期展示常驻品牌标识、全集选集横滑预览轨与【下载 APP 免费看全集】悬浮引导；
   - 播完后弹出下载卡片；微信内点击下载提供右上角“在浏览器中打开”蒙层；
   - 根路径 `/` 承载官方产品特性介绍、截图展示与 APK 扫码/点击直链下载。

### 2.2 客户端交互与内容体验需求
1. **大视界触底无感翻页**：
   - 拔除手动点击按钮，由 `IntersectionObserver` 监听底部哨兵元素，离底 200px 时静默追加下一页；
2. **3.5:3.5:3 推荐混排**：
   - 首页瀑布流严格按 **35% AI精品 + 35% 全网热门 + 30% 口碑破圈** 黄金比例交错编织；
   - 卡片左上角悬浮极简微光角标：【AI】（冰蓝）、【热门】（琥珀金）、【推荐】（象牙白）；
3. **搜索与实时榜单**：
   - 搜索框支持直接键盘输入，200ms 防抖呼出下拉联想词列表；
   - 设立【总热播榜】、【实时新剧榜】、【AI先锋榜】专区；
   - 提供【全部 · 已完结 · 连载中】状态过滤与【最热 · 最新】排序切换。

## 三、 外部资源与云端基础设施边界：网络上能提供什么

### 3.1 外部数据源（上游源）客观现状
1. **历史既有底库资产 (`data/library.json`)**：
   - 文件体积 22.4 MB，收录完整离线数据 14,094 部；
   - 包含红果短剧（2,188 部）、黄果AI（2,263 部）、帝果（3,410 部）、黄豆（2,501 部）、魔都（1,001 部）等多源元数据；
   - 包含《归墟》系列（9 部）、《我的妹妹不可爱》（3 部）、《万物生》（2 部）等标杆 AI 短剧；
2. **红果短剧 (Hongguo) 线上接口**：
   - 具备独立的 `/category/ai-drama` 与 `/rank/hot-ai-drama` 专区（实时收录 24 部高热精品 AI 短剧）；
   - 具备公开站内搜索路由 `hongguoduanju.com/search/<kw>`；
   - 具备经复核可用的流媒体播放解析接口（支持 App API 密文提取与本地 AES-128 解密）；
3. **通用影视采集源 (Modu)**：
   - 具备公开 JSON 接口（`caiji.moduapi.cc`）；
   - 包含短剧（`tid=38`，3.4 万部）、AI漫剧（`tid=42`，1,897 部）及院线电影、动漫、纪录片；
   - 提供免 CORS 的 1080P HLS 直出流媒体切片。

### 3.2 Cloudflare Serverless 基础设施特性与配额红线
依照 Cloudflare 官方产品规格与 Free Tier 配额定义：

| 基础设施组件 | 核心功能与工作模式 | 免费配额与计费规则 | 最优承载目标 | 严禁反模式 |
| :--- | :--- | :--- | :--- | :--- |
| **边缘缓存<br>(Workers Caching)** | 基于 HTTP `Cache-Control` 的全球边缘缓存。**命中时直接在边缘返回响应，不执行 Worker 脚本，不计入 D1 读配额，不消耗 CPU 时间**。 | 与 CDN 流量绑定，按命中规则分发。 | 首页与分类已混排片单 (`/api/catalog`)、全网综合榜单 (`/api/rankings`)、高频搜索结果 (`/api/search`)。<br>TTL 建议设为 300 秒 (5分钟)。 | 严禁用易失性缓存存储需要长期持久化的数据。 |
| **键值存储<br>(Workers KV)** | 全球分布式只读优先 Key-Value 存储。边缘读取极快（毫秒级），写入需最长 60 秒达到全球最终一致性。 | • 读取：**100,000 次/天**<br>• 写入：**1,000 次/天**<br>• 存储：**1 GB** | 空中多源路由配置 (`config:sources`)、商业化与阶梯定价 (`config:monetization`)、客户端版本检测 (`config:version`)。 | 严禁将 KV 作为高频动态写入的缓存层。 |
| **关系型数据库<br>(Cloudflare D1)** | 分布式 SQLite 实例，支持标准 SQL、强事务与索引。**按行读写计费**。 | • 行读：**5,000,000 行/天**<br>• 行写：**100,000 行/天**<br>• 存储：**5 GB** | **仅承载 4 张强一致核心业务表**：<br>1. 卡密表 (`card_coupons`)<br>2. 设备激活表 (`devices`)<br>3. 多端断点表 (`cloud_watch_history`)<br>4. 偏好画像表 (`cloud_user_profile`)。 | **严禁在 D1 中全量存储上万部视频元数据和 FTS5 全文倒排索引**，严禁跑批全表扫描！ |
| **对象存储<br>(Cloudflare R2)** | S3 兼容海量二进制存储。**承诺永久免收出网流量费 (0 Egress Fee)**。 | • 存储：**10 GB**<br>• Class A 写：1,000,000 次/月<br>• Class B 读：10,000,000 次/月 | 正式发布版 Android APK 文件 (`/dl/latest/android`)、数据库 SQL 备份归档。 | 严禁存储小尺寸、高频增删的离散结构化数据。 |

## 四、 架构解法与系统拓扑

### 4.1 核心架构模式：云端多源混合中枢 + 边缘缓存 (Model 3)
放弃“让客户端直接连接多个第三方 URL”的暴露模式，也放弃“在云端 D1 数据库死存上万部元数据”的过载模式。

```
┌────────────────────────────────────────────────────────────────────────┐
│                   【系统三层解耦拓扑与通信边界】                       │
├────────────────────────────────────────────────────────────────────────┤
│ 【层级 1：客户端应用 (Capacitor 7 + TypeScript)】                      │
│   • 唯一对外请求基准域：https://play.prismos.org                       │
│   • 本地无源概念，接收标准化 ContentItem 实体                          │
│   • 负责：触底无感滚动、搜索动态联想、本地 3.5:3.5:3 混排、离场断点同步│
├────────────────────────────────────────────────────────────────────────┤
│                                  │ (HTTPS 规范接口)                    │
│                                  ▼                                     │
│ 【层级 2：Cloudflare Workers 边缘中枢】                                │
│   • 承载端点：/api/catalog, /api/search, /api/rankings, /api/user/sync  │
│   • 业务编织：聚合上游多源，去重归并，抹除第三方品牌，统一封装线路代号 │
│   • 分层存储分配：                                                     │
│     - 边缘缓存 (Cache API): 缓存片单与榜单 (TTL 300s)，扛住 99% 读流量 │
│     - Workers KV: 存储航线配置、商业化政策与版本号                     │
│     - Cloudflare D1: 仅管理卡密核销与多端同步记录                      │
│     - Cloudflare R2: 承载官方 APK 安装包下载                           │
├────────────────────────────────────────────────────────────────────────┤
│                                  │ (受控向外聚合，APP 物理绝缘)        │
│                                  ▼                                     │
│ 【层级 3：受控上游源】                                                 │
│   • 红果专线（精品 AI 短剧、全网热播榜单）                             │
│   • 综合专线（海量短剧、院线电影、动漫与纪录片）                       │
└────────────────────────────────────────────────────────────────────────┘
```

### 4.2 存储分工与防熔断对照表
| 业务数据项 | 归属存储层 | 读取时 D1 消耗 | 理由与生命周期 |
| :--- | :--- | :--- | :--- |
| **首页/分类片单** | **边缘缓存 (Workers Caching)** | **0 行** | TTL 300 秒，边缘直接返回，不入 D1，不耗 CPU。 |
| **排行榜单** | **边缘缓存 (Workers Caching)** | **0 行** | TTL 300 秒，全网共享，聚合红果与大盘实时榜单。 |
| **搜索联想与高频词** | **边缘缓存 (Workers Caching)** | **0 行** | TTL 600 秒，高频热词边缘秒出。 |
| **空中源配置 (航线图)** | **Workers KV (`config:sources`)** | **0 行** | 仅在 Worker 冷启动或配置更新时读取，全球广播。 |
| **商业化与版本号** | **Workers KV (`config:*`)** | **0 行** | 静态策略，免 D1 查询。 |
| **卡密核销记录** | **Cloudflare D1 (`card_coupons`)** | 仅按需读写 1 行 | 强一致事务，仅在用户输入卡密时触发。 |
| **多端续播断点** | **Cloudflare D1 (`cloud_watch_history`)** | 单次上报写 1 行 | 仅限会员在退出播放/退出应用时触发，极低频。 |
| **题材偏好画像** | **Cloudflare D1 (`cloud_user_profile`)** | 单次上报写 1 行 | 仅限会员在离场时更新，单剧单行覆盖。 |
| **APK 安装包文件** | **Cloudflare R2** | **0 行** | 零出网流量费，支持大文件断点续传。 |

## 五、 重构实施步骤与验收标准

### 5.1 实施阶段与工序排期
1. **阶段一：分享播放修复与裂变门户落地（P0 紧急）**：
   - 重构 `edge/src/html/share-page.ts`：引入双通道播放引擎（原生 HLS + Hls.js 兜底），注入微信同层播放属性，解决安卓微信与浏览器黑屏；
   - 落地页增加全生命周期金色常驻品牌条、选集横滑预览轨与【下载 APP】悬浮 CTA，添加微信内右上角“在浏览器中打开”蒙层；
   - 消除根路径 404，在 `play.prismos.org/` 部署官方产品介绍与 APK 下载页面。
2. **阶段二：客户端交互与体验还原**：
   - 改造 `src/views/home-view.ts`：拔除手动【加载更多】按钮，装配 `IntersectionObserver` 触底自动追加下一页；
   - 改造搜索栏：实现 200ms 防抖的动态联想补全浮层（对接 `/api/search/suggestions`）；
   - 补齐分类栏右侧的状态过滤（全部/已完结/连载中）与排序切换（最热/最新）；
   - 恢复榜单专区视图（总热播榜/新剧榜/AI先锋榜）。
3. **阶段三：云端多源混合中枢与边缘缓存挂载**：
   - 将 `edge/src/index.ts` 架构声明更新为“云端受控多源聚合”模式（更新对应 ADR）；
   - 引入红果 AI 短剧专线与综合源，实现云端同名去重与格式规约，统一抹除第三方原厂名称；
   - 将 `type_id = 42`（1,897 部 AI 漫剧）与红果 AI 剧完整收编入【短剧精选】频道，确保 `is_ai = 1` 稳定供给；
   - 为 `/api/catalog`、`/api/rankings`、`/api/search` 挂载边缘缓存，TTL 设为 300 秒，验证 D1 零读数。
4. **阶段四：全链路回归与出厂验证**：
   - 运行全量自动化测试套件与 P0 红线静态扫描（零 Emoji、零紫粉渐变、零裸 Hex、零第三方名字）；
   - 编译最新 Release APK，进行真机全功能回归。

### 5.2 刚性验收指标 (Acceptance Criteria)
- **AC-R1（分享播放率）**：分享链接在微信内置浏览器、手机 Chrome、桌面 Edge 任意环境打开，点击即可起播，成功率达到 100%；
- **AC-R2（官网可达性）**：访问 `https://play.prismos.org/` 返回 HTTP 200 官方介绍与下载页面，无 404；
- **AC-R3（瀑布流连贯性）**：客户端首页向下滑动平滑连续，无需任何手动点击按钮即可无限载入后续内容；
- **AC-R4（AI推荐可见性）**：短剧精选首屏及后续瀑布流中，稳定呈现带有冰蓝【AI】角标的剧目，3.5:3.5:3 规则生效且无降级掩盖；
- **AC-R5（D1配额安全性）**：客户端连续快速刷新 50 次，云端 D1 数据库行读增量严格为 0（全部由边缘缓存命中返回）。
