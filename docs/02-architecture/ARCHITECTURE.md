## 一、 架构演进与技术选型定案

### 1.1 为什么彻底告别旧版“WebView 裸奔 + 子进程拉起 Go 二进制”？

在初代实验项目（**历史工程** `D:\DEV\guoguo-juku`，非当前仓库；当前工程为 `D:\DEV\prism-play`）中，存在以下 5 大历史架构硬伤，导致强烈的“网页套壳感”与维护隐患：
1. **窗口伪沉浸**：使用 Android 4.4 时代的过时 `setSystemUiVisibility`，未接入现代 `WindowInsets`，在全面屏/挖孔屏手机上留有生硬黑边；
2. **后台子进程隐患**：在 Android 内部通过 `ProcessBuilder` 强行拉起编译好的 Linux ELF 二进制（`juku_arm64`）监听 `127.0.0.1:8999`，不仅使安装包膨胀 15MB+，更触犯 Android 10+ 的 `W^X` 安全沙箱红线，极易被国产 OS（澎湃OS/HarmonyOS/ColorOS）后台静默查杀；
3. **播放状态监控业余**：通过后台线程每秒向网页注入一段 JS 轮询查找 `<video>` 标签状态，极其耗电且不稳定；
4. **站源硬编码失控**：客户端本地写死上游接口地址，一旦上游变更域名或失效，客户端即刻沦为僵尸包；
5. **技术血统割裂**：与主站 `prismos.org`（React 19 / Vite / Tailwind 现代前端体系）完全脱节。

### 1.2 商业版 2.0 终局技术选型：【方案 B】现代全栈 + Cloudflare 边缘云脑

经过严谨的多维对比，正式锁定 **【方案 B：Capacitor 7 + TypeScript + ArtPlayer.js + Cloudflare Serverless】**：

| 架构层级 | 锁定技术选型 | 版本锚定 | 选型核心理由 |
| :--- | :--- | :---: | :--- |

## 三、 核心工程机制设计

### 3.1 动态“大视界”频道与播放源空中调度机制
1. **彻底解耦客户端与具体站源**：
   - 客户端代码库中**零硬编码上游域名**；
   - 有公开本地快照时先渲染缓存，再向 `GET https://play.prismos.org/api/channels` 与 `/api/catalog/changes` 同步；`/api/sources` 只供必要的源状态诊断或服务端能力提示，客户端不据此直接发起媒体请求。KV 可缓存公开拓扑/健康指标，不能决定私密准入或撤片。
2. **私密频道双重准入隔离**：
   - **网络层隔离**：`/api/channels`、`/api/sources`、`/api/catalog`、`/api/titles/*`、`/api/episodes/*/playback` 必须**同时**校验「有效 B/Y/S 授权」与「当次私密会话凭据 `X-Private-Session`」；两者缺一，`private` 节点与数据在响应 JSON 中完全不存在，而不是返回“可见但锁定”；
   - **会话凭据不落盘**：客户端只在内存持有凭据，冷启动、完全退出或会话结束即失效；服务端不持久化开启状态或凭据明文。主动关闭需存放不含私密内容身份的 token 摘要撤销墓碑直到原凭据过期，并逐请求核查；否则无法兑现 DELETE 立即失效；
   - **诚实边界**：服务端只能证明收到显式开启请求，无法验证用户是否真的在设备上完成点击，此局限必须写入交付说明，不得宣称绝对不可绕过；
   - **视图层隔离**：未满足条件时 DOM 树中完全不渲染私密频道节点、二级分类与海报。
3. **服务端择源与客户端故障重解析**：
   - 服务端在已准入的同一分集健康候选中择源，`/api/episodes/{episodeId}/playback` 只返回一个同源短时代理句柄；客户端拉流失败时记录当前进度，以同一 episodeId 有界重取（最多 2 次）并尝试 Seek 恢复；不得凭同名剧目切到另一个作品。若所有候选不可用须返回明确不可用状态，不作无限重试。
   - 客户端**只**访问 `play.prismos.org` 同源代理，真实上游地址仅存 D1，由代理做白名单与防 SSRF 校验；不要求客户端并发探测真实源。

### 3.2 极简分享“点开即播、播完截流”机制
1. **统一短链路由**：`https://play.prismos.org/s/:drama_id?ep=1&ref=INVITE_CODE`；
2. **边缘 SSR 极速响应**：Cloudflare Worker 直接返回内联 ArtPlayer 与**当前单集**代理流地址的轻量 H5 页面；
3. **自动播放只作尝试**：浏览器与微信对带声音自动播放有策略限制，被拒绝时页面必须提供单次点击“播放本集”兜底，不得把自动播放写成绝对承诺；
4. **精准截流状态机**：监听 `video:ended` 事件，一旦**当前集**播放结束，立即淡出控制条并弹出引导卡片：“本集已播放完毕，如果继续看，请下载【光影Play】”，点击跳转 `/dl/latest/android`；
5. **微信引导只在下载链路**：`/s` 不做跳出引导，`/dl` 仅提供合规下载操作指引，不承诺绕过平台限制；
6. **404 铁律**：私密剧目与未知剧目在 `/s` 一律 404，且不泄露任何元信息。

### 3.3 预制卡密条件原子核销与 14 天离线授权
1. **卡密结构**：兼容 `GY-Q90D-A7F2-8899` 等已定实例，第二段首字符 Q/A/B/Y/S，长度 4～5 位；真实档位、时长仅以 D1 记录为准，具体表达式以 OpenAPI 正本为准；仅 B/Y/S 具备个人探索资格；
2. **D1 条件原子核销**：不依赖交互式 `BEGIN/COMMIT`；新设备按 `status IN ('UNUSED','ACTIVE') AND device_count < max_devices` 条件更新，计数、绑定与设备授权在单次原子写入单元完成，失败不得落部分行；同设备复用须先验证当前卡密与设备状态。`batch()` 事务语义与跨请求并发必须在真实 D1 用第 10/11 台竞态及吊销场景验证，SQLite 单连接样本不等于 D1 并发结果；
3. **异常风控**：成功绑定上限严格 10 台；被拒绝的**不同**设备去重计数超过 20 时置 `is_abnormal = 1`；
4. **离线授权（非离线播放）**：边缘以 **Ed25519 私钥**签发 JWT，客户端仅内置**公钥**验签；设备 ID 为随机安装标识，格式符合 OpenAPI 的 `GY-` 加 8 位大写字母数字，不能视作不可伪造硬件证明；离线期用于校验授权状态与档位，最长 14 天；本期只允许浏览缓存的公开目录与缩略海报，断网不提供视频播放，私密内容亦不参与缓存。联网撤销不能即时通知离线设备，最多等待本地凭证/14 天窗口到期后停止显示有效授权；离线令牌有效期和最后在线校验时间需取更早者。

### 3.4 已配置来源的内容加工与索引
- 仅处理明确配置的来源，不做全网自动发现；来源适配器按游标增量读取元数据，任务以 `(provider_id, source_item_id, revision)` 保证幂等；`source_records` 保存 `attempt_count/next_attempt_at/error_code`，单条最多自动重试 3 次，超过后自动隔离并保留原因；新修订可重试，不允许无限失败循环。原始来源记录、来源分集映射与规范作品分离，失败记录保留以便重试；Crons 负责唤醒及巡检，不要求一次跑完全量抓取。
- 本期直接按来源自带分类录入，不做复杂的受控分类与 AI 标签；跨来源自动归并必须有 `trusted_work_mappings` 中可追溯的跨源证据引用，严禁仅凭同名跨源合并。D1 保存发布状态，上架后生成公开 FTS 词法索引和目录快照；撤片先拒绝新的播放和分享，再清理异步索引。
- D1 FTS5 配合预计算汉字/拼音词项承担词法候选；中文单字、双字与多音字须通过固定样本验证，不假设 `unicode61` 自动完成中文分词。完整搜索 page 本期为尽力分页，索引变更可能造成跨页重复/遗漏，客户端按 ID 去重；公开目录的强一致快照协议与搜索分页不同。Workers AI 与 Vectorize 语义检索统一收归 v2.1+。

### 3.5 客户端公开缓存与网络协议
- Android 本期持久化四公开频道的频道、分页目录、详情摘要、缩略海报与非私密续播；启动先看本地快照，再按版本与游标顺序拉增量事件（upsert/delete）；游标失效回退完整快照。目录缓存写入使用临时快照并在全部同修订分页成功后原子替换；空间不足/进程中断则保留旧快照，禁止混合两个版本。图片按稳定资源 ID 加 ETag/内容指纹复用，仅变更时下载；公开海报默认容量 128 MiB、元数据 20 MiB，海报与旧分页可 LRU 淘汰，续播进度和凭证不受缓存淘汰影响。
- 个人探索在本地数据库、图片磁盘缓存、搜索历史、预加载与备份中均零落盘；客户端不带私密会话凭据时云端响应也不含该分类。断网仅显示已缓存公开信息，不承诺视频离线播放；播放鉴权、分享与撤片以在线 D1 为准。KV 最终一致，不能决定撤片是否放行。
- 分享 H5 与 Android 为本期交付面；PC 下载直链与桌面构建延后。`/api/episodes/{episodeId}/playback` 由服务端优选单个代理 URL，故障由客户端重新解析获取候选，不向客户端暴露真实源。代理将 HLS 主/子清单、分片/密钥 URI、字幕的引用重写为带内容身份的受控地址，每次请求（含分片/Range）回 D1 复核发布状态；私密必须绑定当次会话并禁止公共缓存，只持有代理 URL 不足以放行。Range/206 与 Content-Type 用授权样本实测。浏览器/原生 HLS 分片请求未必能携带自定义会话头，私密取流必须由同进程受控转发层逐次注入授权和会话凭据；若需改为可撤销能力凭据须先更新 OpenAPI 再真机验证；未验证前私密视频不对用户开放，不能以“短时 URL”绕过双准入。`/api/device/ping` 若宣称续期则必须下发新凭证。

### 3.6 端侧四大存储域与系统备份隔离架构 (落实 M-8 / 消除 R-14)
端侧严格实施四级资产物理隔离，严禁将凭证与历史混库：
1. **安全凭证域**：Android Keystore 硬件密文存储 JWT 与 `deviceId`，配置 `dataExtractionRules` 严格排除在系统备份外（防跨机不可解密导致授权损毁）；
2. **追剧与历史域**：端侧 SQLite (`prism_local.db` -> `local_watch_history` 表)，最多存 500 部剧秒级断点；**纳入 Android 备份白名单**，换机无感延续进度；支持用户单键“清空历史”（只清本表，不清凭证与海报）；
3. **公开缓存域**：缩略海报 (上限 128 MiB) 与目录快照 (上限 20 MiB)，LRU 淘汰，排除在备份外，联网自动恢复；
4. **私密禁存域**：个人探索全流程 RAM-Only，底层数据库与文件拦截器物理屏蔽私密写盘，冷启动/退出即焚。

## 五、 工作包拆解与量化估算（LOC + Token 口径）

| 工作包 | 核心交付内容 | 预计代码/配置量 | 预计 Token 消耗 | 依赖关系 |
| :--- | :--- | :---: | :---: | :--- |
| **阶段 0：施工前契约门禁** | 三层契约、合成样本矩阵；账号权限仅标未知不绑定资源，不部署不写业务代码 | 文档约 300–600 LOC；校验脚本如留仓约 100–250 LOC | 约 20k–45k Tokens | 静态/合成契约可验；账号额度和真实环境列为阶段 1 入口，不冒充已通过 |
| **阶段 1：云端内容事实与商业核心** | D1 新库迁移、内容来源适配/分类/归并/发布与撤片；卡密/会话/签名核心，合成数据集成测试 | 约 1,400–2,400 LOC；测试 450–850 LOC；文档 150–300 LOC | 约 90k–160k Tokens | 阶段 0；归并与核销幂等、误并隔离、AI 失败续做通过 |
| **阶段 2：传输与同步** | 搜索/增量目录协议、封面版本、媒体代理与分享 H5；逐请求准入和契约测试 | 约 1,300–2,200 LOC；测试 450–800 LOC；文档 120–250 LOC | 约 80k–145k Tokens | 阶段 1；游标断页回退、撤片拒绝、私密无旁路通过 |
| **阶段 3：客户端与 Android 宿主** | 搜索交互、公开快照/海报持久缓存、播放器与原生桥、私密零落盘 | 约 1,900–3,000 LOC；测试 550–1,000 LOC；文档 120–240 LOC | 约 105k–185k Tokens | 阶段 2 契约；冷启/断网/输入法/后台和缓存真机路径通过 |
| **阶段 4：集中回归与交付** | AC-01～18、素材授权准入、云资源及用量核对、签名/代理/分享和 Android 包发布前检查 | 约 300–700 LOC；测试 500–950 LOC；文档 150–300 LOC | 约 45k–90k Tokens | P0 零缺陷、构建可复现；未取得必要素材/账号权限则不得对外发布 |

> 均为范围级粗估，不是已投入或批准的费用：业务/配置约 4,900–8,300 LOC，测试约 2,050–3,850 LOC（阶段 0 若留仓另有校验脚本 100–250 LOC），文档约 840–1,690 LOC；总约 340k–625k Tokens。以各阶段真实样本、平台额度和测试数据重估，不再使用旧版 5,000 LOC/135k Tokens 或“精简 60%”未经测量的结论。三个层面是架构视图，阶段 1→4 是依赖视图；不互相替代。
